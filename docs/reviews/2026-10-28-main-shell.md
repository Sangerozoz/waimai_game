# 主界面、需求弹窗与配送中餐损提示

2026-10-28，按用户图片标注与本聊天补充要求实现。第一阶段仍待用户复验，没有启动第二阶段。

## 本轮结果

- 顶部为圆形头像占位、澄川骑手昵称、等级经验、余额、评价；底部招募/车辆/抢单/站点/地图五入口。抢单突出，车辆打开原有车库；招募/站点未上线灰色且无点击处理，地图显示当前页。配送中抢单和车辆禁用，余额不足或已达县城上限时升级按钮同样禁用。被动收益整个信息项尚不显示。
- 头像/导航仅为代码占位，正式图标由用户生成后告知路径再导入，没有新增假账号、收益或经营系统。
- 配送时底部导航保留，原活动面板上移118设计像素、地图高度同步减少118；右下角定位始终在地图内。新档及旧档经营状态不改。
- 到店实际停2秒，状态明确“正在取餐中 · n秒”。当前放门口到达后自动弹必选需求窗，未选择不结算，遮罩不跳过；刷新或窗口重建仍从业务arrived状态展示。选择后关闭并打开结算，重复释放不重复结算。普通单仍自动结算。
- 已抽中餐损的订单，取餐后的送餐距离中段显示“路程颠簸，餐品损坏了”，2秒自动消失，配送不暂停。无损订单不弹，瞬间跨到送达的大帧不在结算后补放。UI重建保留剩余展示时间，后台冻结。
- 新可选布尔字段damageNoticeShown保存每单已领取的展示机会；旧档缺失按未展示处理，坏类型拒绝。仍使用出发时抽中的原餐损，展示不新增随机消耗、损坏、扣款或奖励；原回执相等回归通过。旧档运动和结算时钟不变，事件按道路秒逐段还原实际米数定位。
