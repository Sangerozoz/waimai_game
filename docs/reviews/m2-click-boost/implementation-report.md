## 实际接入

`TripClock.ts` 新增临时 `ClickBoost` 状态，`MapSample.ts` 接入专用“点击加速 ×倍率”控件及行程推进。控件在订单卡上方的地图区域居中，与左侧站点及右侧定位控件留开空间，只在当前新 profile 的实际移动段显示。没有素材制作或餐品图接入。

参数按已定候选实现：基础倍率 1，上限精确为 10/3，每有效击 +0.5，按真实前台秒线性衰减 1.5。输入以 `performance.now()` 的单调时间戳入队，任意连续一秒最多接受 8 次，额外输入不入队、不增加倍率。倍率显示保留两位小数。

每帧取 `ForegroundClock` 同一时间轴的区间，依次切分点击时刻，以及倍率衰减到 1 的时刻。在无点击的长度 d 区间中，令 q=min(d,(B−1)/1.5)，积分为 d+(B−1)q−0.75q²；点击时再将倍率提高至 min(10/3,B+0.5)。最终以积分/dt 作为该帧平均倍率传入已有 `OrderBook.advance(dt,multiplier)`，不使用帧末倍率乘整个 dt。零 dt 不推进。

位移和游戏行程时间继续读取同一份 `elapsed`，通过既有 `travelDelta` 与 `advanceHandoff` 推进；到取餐点、服务结束和送达点仍按既有边界截断，不把剩余帧跨入玩家确认后的下一段。人工点击出发、取餐或去配送导致阶段切换时，清空倍率并重置前台帧时钟，防止把确认前的时间归到新阶段。

## 输入和生命周期

- 仅精确匹配 `m2-120-service60-v1` 且处于 `toPickup` / `toDropoff` 的 running 订单可用；旧活动订单继续原时钟，未迁移 schema 或保存加速状态。
- 控件要求从自身开始、在自身范围内结束、位移不超过 7 UI 像素的单点操作。拖动、取消、多指会取消该次输入；全局触摸开始监听用于识别第二根手指落在地图等其他位置的情形，并在节点销毁时解绑。控件阻断事件传播，地图拖缩放及其他按钮不会调用加速。
- 到站、服务、待取餐/待配送、规划、结算、暂停、后台、入口门禁、保存失败和只读页面均不可加速；这些边界清空倍率、排队输入与限流记录。恢复前台跳过首帧，暂停恢复与人工阶段切换重置帧时钟，不补算隐藏时间。读档创建新临时状态，倍率从 1 开始。
- 保存失败沿用原 pending 提交冻结与重试，失败时立即清空加速。按钮的倍率标签随更新刷新，不以视觉反馈决定业务时间。
