## 范围与当前差距

- 当前来源/份数/备注已在DeliveryOffer及OrderPresentation启用；新候选来源约20%、旧无字段兼容，不重新设计。
- 当前卡片逐行堆叠、路线纵列；收卡/非配送弹窗期间到达仍可能延后展示；此轮以主动触达覆盖前轮静默返回约定。
- 当前OrderBook自动到店停2秒并继续，door必须弹窗回答；新增手动取餐/送餐出发切片，不同时做点击加速、多单、体力、NPC或新经济。
- 小红“取消订单”放“去取餐”左侧；X始终只收起。取消可用阶段/费用/候选去向均待用户答复，不能复用现cancel冒充途中取消。
- 未收到答复前可完成布局与其他流程，取消业务不启用、不发明罚款；PM落实决定后补明确阶段守卫与回退行为。

## 新单状态机与操作

新活动显式workflowVersion=manual-handoff-1（具体字段名由开发定），mode可兼容旧聚合态，但phase才决定操作合法性。
缺标记活动一律旧流程，不凭elapsed猜测迁移。建议新单从接取时冻结标记，已有候选可保留内容不重抽。

| phase | 进入条件/按钮 | 可推进范围与退出 |
| --- | --- | --- |
| planning | 接单；底部去取餐 | 固定路线/期限；去取餐只提交一次出发与既有餐损结果，进入toPickup |
| toPickup | 首段行驶 | 只到pickupIndex，截断本帧余量→awaitPickup；骑手停在真实商家点 |
| awaitPickup | 主动展开卡；主按钮取餐 | 不自动消耗取餐服务；点击提交后进入picking |
| picking | 显示取餐中，主按钮禁用 | 累计2秒前台服务，持久化已耗时；完成→awaitDeliveryStart，不自动出发 |
| awaitDeliveryStart | 主按钮去送餐 | 点击一次进入toDropoff；不重抽餐损，不重置路线/期限 |
| toDropoff | 后段行驶 | 只到终点；自动按已有door语义执行→唯一结算→settled |
| settled | 优先展示结算 | 本单已入账；确认/X/遮罩沿用finish+save→干净首页，不恢复残旧卡 |

- 人工边界、服务完成边界都丢弃本帧剩余dt；大dt不能一帧自动取餐、跳过去送餐或完成多个阶段。
- 所有等待态停在原地点；本切片继续M1行驶换算、原时限和2现实秒服务口径，等待点击/服务不新增游戏分钟或时限惩罚。
- 不引入M2的120倍新钟/服务1游戏分钟；前后台和跨页等待不算行驶，后台完全冻结，回前台丢弃首帧补偿dt。
- 新单door自动以doorAnswer=true按门口备注执行，无要求用null；不弹交付要求，不偷偷视为拒绝或暗扣评分。
- buyerNote自由文本只展示，不能从任意文本推断新扣分条件；唯一可执行需求仍是已有demand。
- 旧活动缺workflow标记：原自动取餐、原door选择、原结果/时钟继续直至完成；已抽餐损和旧回执不重算。

## 主动触达与优先级

1. 结算成功最高优先：关闭非配送弹窗/大厅/旧配送卡，展开本单结算，停止显示已完成进度。
2. 到店待取餐次优先：关闭非配送弹窗，回当前配送卡，突出“取餐”；镜头回商家，不依赖再点中央入口。
3. 取餐服务完成：突出“去送餐”；若用户在其他弹窗，回当前卡，避免服务完成后无入口提示。
4. 以上无关键事件时，保持菜单/收卡/子页返回原viewState；中央idle“抢单”、active“订单”，不另开大厅。
- 关键事件覆盖普通子弹窗返回栈，不能关闭后自动重新打开账单把取餐/结算再盖住；允许用户稍后主动查看。
- 用持久化eventKey=订单ID+workflowVersion+事件种类+唯一阶段序号，关键事件随状态快照保存，确认/消费状态可恢复。
- 单次运行只派发一次相同key；重载有尚待处理事件要重呈现，已确认不得重复打断；不能以“已弹过”掩盖未完成取餐动作。
- UI重建只还原视图，不生成业务事件；重复渲染不再弹。后台只保留pending事件，恢复前台后按优先级消费。
- 到终点若保存失败，展示“结算保存待重试”的原错误反馈，保持同一结果；不伪称持久化到账，不重抽/重复登记。

## 精简结算与真实扣减

- 顺序仅：本单收益大字→一行准时/晚到、餐损、按备注→确有金额影响的分解→评价变化/经验各一次。
- 删除乘数、钱包余额、评级前后串、重复XP；评价建议“评价−3”或“评价+2”，经验“经验+10”，直接用回执字段。
- 当前公式用结算后ratingAfter影响收益，再乘餐损保留率；晚到只有评分−3，没有独立现金罚款。
- 显示“晚到影响收益−¥X”“餐损影响收益−¥Y”，不得写“超时罚款”；为0整行省略，可保留事实“晚到，评价受影响”。
- 用唯一冻结before、offer、ruleVersion和实际outcome调用对应纯结算器，计算只读对照，不提交、不写账单、不改变实际钱。
- 固定分解顺序：I0=准时且完好；I1=实际准时/晚到且完好；I2=实际时限与实际餐损，即真实incomeCents。
- 三次均保留实际doorAnswer、其余冻结参数；准时对照displaySeconds=min(实际值,deadlineSeconds)，不改车/等级/价格/备注回答。
- 晚到影响=I0−I1；餐损影响=I1−I2（含餐损引起的评价变化及折损）；显示“准时完好对照¥I0”时说明为对照收益，不称原应付额。
- I0−晚到影响−餐损影响必须精确等于回执incomeCents；逐次按原整数分舍入后相减，禁止自行拆乘数再四舍五入。
- 评价封顶/保底可能让某项差为0，正常省略；异常差为负时标“影响+¥”而不伪称扣款，并记录供开发复核。
- 旧回执若有拒绝门口备注，按真实回答展示“未按备注”，不改为已遵守；对照仍冻结该回答，不把备注影响塞给餐损。
