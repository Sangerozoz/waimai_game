# 县城视觉制作方法：独立只读判断

2026-11-03｜给PM｜仅已有PNG目视、源码/数据片段及官方能力资料核验；未运行游戏、测试、typecheck、浏览器、截图渲染或存档操作。结论是诊断与建议，不是新方案已验证。

**结论：目前确实存在制作方法与目标不匹配的问题，证据不足以归咎于Cocos或断言2D做不到。** 当前实现适合坐标/密度预览；将其通用体块铺满、再重复贴窗格，不能承担目标的精细街景生产。建议暂停这种外观的全县复制，以一个真实3D固定机位街景小样建立方法，但不立即迁移整张地图。

**事实与推断分开看：**

- **已有图事实：** 最新拒绝图（临时文件`codex-clipboard-8cc402d5-f065-4679-b66a-aa26fd70c0d3.png`）表现为大量同构楼体、整片浅屋顶、密集重复小窗和少量树；[目标图](../../art/2026-11-03-sample-fidelity-rework/user-target-concept.png)具有玻璃通高分区、凹凸转角/退台、遮阳篷、屋顶设备组、路缘/铺装、树冠层次、街灯与连贯投影。后者不是仅靠颜色或单张墙面纹理建立的。
- **源码事实：** [sample.js](../../../delivery-game/county-sample/sample.js:3)使用Canvas2D，手写地面仿射投影、按对象中心排序；道路逐线段画四边形，人行道是加宽路带。[street-facades.js](../../../delivery-game/county-sample/street-facades.js:4)将足迹拉高，约每3.6m划一窗格，重复同一上层图，地面阴影固定偏移`[1.5,-2.8]`，屋顶至多加一个同类盒体。数据虽有`module/styleProfile`，该绘制器没有用它们塑造转角店屋、公寓等差异轮廓。**推断：** 丰富贴图继续塞进此规则，主要增加重复细节，难改变整体沙盘观感。
- **引擎事实：** 项目声明Cocos Creator 3.8.8；官方3.8支持[正交/透视相机](https://docs.cocos.com/creator/3.8/manual/en/editor/components/camera-component.html)、[静态网格/材质与投受影](https://docs.cocos.com/creator/3.8/manual/en/engine/renderable/model-component.html)。因此当前Canvas表现不能代表引擎上限。真实3D可统一空间与遮挡计算；风格、模型质量、材质和灯光仍需制作。
- **镜头与流程推断：** 拒绝图显示几十栋楼，目标突出少数完整街景主体；应先统一建筑、车、人行道在屏幕中的相对尺寸再比较。仅放大现有模型仍暴露缺失的体块/细节。数据完整、对象数与构建完成不是视觉门槛；此前没有先形成一块达标街景便扩展密度，是关键生产顺序问题。不能用概念图反推唯一精确物理机位，也不能让用户重复选择已确定风格。

| 路线 | 适配与价值 | 真实成本/限制 |
| --- | --- | --- |
| 继续2D模块化精修 | 能保留投影与绘制框架；精绘分层体块/贴片可达到丰富固定视角画面 | 任意方向和凹足迹需额外转角/端头版本、遮挡切分、阴影一致性规则；必须改资产组织与体块，不是再添两张窗图。仅对少量固定建筑划算，县城多形状维护压力高 |
| 固定镜头预渲染2.5D | 可把完整材质与光影烘进分层图片，固定镜头下美术控制强、实时计算少 | 仍需高质量模型或手绘源；单栋图不能随意拉伸旋转适配原足迹。逐块烘焙适配性好但增加图集/分块成本；路线、车辆的前后遮挡需深度/遮罩方案，缩放受像素分辨率限制 |
| Cocos真实3D模块＋风格化材质光照 | 最适合保留多方向足迹、可缩放地图和一致空间关系；路网地面坐标映射到3D地面即可复用 | 足迹挤出只提供底壳；凹角、转角、立面节奏、屋面、UV/法线、路口路缘仍需模块和算法。前期资产与渲染层投入最高，设备性能和阴影方案未验证；默认PBR/Toon都不自动等于厚涂 |

**独立建议：优先真实3D固定机位的小范围验证，但理由应是空间一致性与后续编辑可控，而不是“3D天然更像目标”。** 对任意足迹更可控仅在已有可靠网格生成、立面分段与转角规则后成立；不能直接把完整店屋模型拉成任意多边形。若近期只能获得精绘固定视角素材，预渲染2.5D仍是合理备选，不应在缺乏资产时承诺3D必定更快。

**最小下一步：** 从原样板选一个真实路口、三栋不同商住楼（转角店屋、玻璃沿街楼、普通住宅；包含一栋不规则原足迹），加一段完整人行道、树、街灯、街边设施及静态骑手尺度参照。固定一个与目标同等近景密度的机位，先建立轮廓、楼层/门窗比例、街面厚度、暖白/玻璃/橙色材质与统一光向，再谈铺县。三栋必须在轮廓和首层设计上可区分，门窗不能缩成重复噪点，树/建筑/设施必须落地且阴影一致；这些是团队按既定目标检查的制作门槛，不是新风格投票。本轮只提出这一范围，没有启动制作或渲染；后续游戏测试仍等用户说“阶段完成”。

**可保留与未验证：** 原浮点路网、足迹、水系、入口ID、蓝红边界、场景索引数据、路线/玩法与只读状态协议可保留；坐标转屏、深度排序和Canvas绘制应由新表现层适配，不能宣称原样无成本复用。模型制作能力与性能预算尚未建立：只读检查未在PATH及常规应用目录发现Blender；Cocos安装目录确有taxi示例的house/road/tree FBX，但未检查授权、拓扑或风格，不算目标可用模块库。项目没有已证实可用的精细商住3D资产库；需实际产出小样才能证明推荐路径。本报告不承诺工期、最终视觉或用户验收。
