# 第五批 runtime/UI 接入

已按 ledger/targets 与 supply/inventory 代理的接口接入，仅修改 V2RuntimeController、V2GameUI 和待执行 UI 测试。Bootstrap 现有显式新建/恢复入口足够，本批无需改动。

- Runtime 每次命令候选只采样一次绝对秒时间，为 Dispatch 注入毫秒时间及本地日键；同一时间驱动 tick/广告结算。候选连同账本通过既有单次 commit 保存后发布，保存失败保留上一份 live。
- 账单为一页连续滚动，依次显示今日、近7日、累计、日期未知的收入、支出、净额和分类明细。迁移期初余额不计收入；NPC 日归属暂未知说明明确显示，累计保留真实收入。
- 整批回执收入按 ledger 中批次订单 ID 提取；补给现金使用 Trip.begin 统一建立的累计费用基线，库存按累计已用数量基线独立展示，不作为现金扣减。自动/手动接批共用领域基线；最后交付或取消时冻结 end 费用/库存，之后补给不漂移本批回执。旧在途缺基线显示未知。
- 首页只显示一个可切换的纯查询目标，展示实际差额及前往按钮；无购买、返利或强制消费副作用。
- 补给滚动面板展示六种商品、实际恢复、现金费用、耗时、库存、最高已购地图开放条件，购买及库存主动选择；满体力/动作/服务时禁用。免费休息保留真实按活动订单的恢复与耗时。
- 自动补给开关、付费授权、库存授权独立。域默认 false；UI 转发现值不附带默认授权；关开不重置 spent，低于已花金额的预算按钮禁用。
- 双列骑手、车辆上详情下三列宫格、五图卡和现有颜色/布局保持。

待执行测试位于 `delivery-game/tests/v2-trip-ui.test.cjs`，覆盖原子时间/保存失败、六补给购买与库存、满体力禁用、自动授权和预算、批次现金与库存、缺基线、账单分类和单目标只读行为。

本批未运行 tests、typecheck、build、游戏页面或实际存档。仅做源文件读取与接口静态核对，未宣称通过测试或美术验收。
