# 补给与在途批次展示实现

2026-11-05，仅修改 `delivery-game/assets/scripts/map-sample/V2GameUI.ts`。实施前已读 implementation-baseline 最新UI段、V2SupplyCatalog、Runtime/GameSession/RouteSession/TripRules接口，并实际打开认可骑手、车辆、订单三张PNG，沿用现有浅蓝面板、深蓝文字、图片按钮与图标。

## 补给

- 六项浅蓝图文卡读取 supplyOptions 的名称、实际恢复、动作秒数、游戏期限推进、价格、库存与最高已购地图开放条件。
- 使用已有 FoodImages 的面/汉堡/奶茶/寿司作补给示意；没有纯净水或瓶装饮料专图，使用已有 energy 图标，不传不存在的食物名触发鸡腿饭兜底。
- 体力条、免费休息独立卡；有批次10秒恢复最多20点且推进期限10分钟，无批次20秒恢复至满且期限不推进。
- 自动补给开关、独立库存授权、独立付费授权、总预算/已花/剩余分区；保留既有0/5/10金币预算操作及已花金额下限。
- 购买/库存按钮仍按 available、unlocked、余额/库存条件启用；服务阶段继续沿原UI条件禁用。手动确认补给后沿原命令返回首页计时。
- 顶部固定“返回原页”和“回到首页”，滚动区域止于底栏上方。

## 在途批次

- 批次摘要显示待完成/已完成、当前阶段、中文天气、体力与暂停说明。
- 只有 planned 展示 runtime.routeChoices；快捷/均衡/平稳以中文显示，读取实际metres/seconds。路由返回同一路径的aliases时合并中文名称，未虚构三条不同路径。
- 已出发时展示当前路线中文名及实际总米数，不提供重新选择；planned无可选路线明确提示检查体力/补给。
- 全批次连续滚动图文卡，不再只截前四项。取送地取route.orders，状态/期限取tripState与dispatch，已完成读取真实receipt入账额。餐品图名沿用大厅现有offerFood展示映射，不把它写入业务；当前订单接口没有权威餐品字段。
- 固定底部继续配送、到店取餐、补给、取消未完成命令。取餐须pickup且没有补给动作；取消说明仅陈述既有规则：完成收入/经验保留、未完成无奖、补给不退。
- 新增tripStage展示helper，首页补给动作名和批次阶段统一中文，未调整时间推进或路线逻辑。

## 核查与限制

已静态回读实际源码，并核对卡片/按钮边界与滚动底部坐标；未运行tests、typecheck、回归、构建或打开游戏/真实存档。尚无此轮运行截图或视觉验收；由父会话统一必要构建与隔离展示核对。未修改domain、经济/体力规则、道路、存档、广告、31人身份/固定报价/五图名，也未覆盖既有配车与升级详情。
