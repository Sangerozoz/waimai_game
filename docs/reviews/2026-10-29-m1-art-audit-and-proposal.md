## 推荐方案A

### 主页

维持顶部白色圆角悬浮卡、无阴影、设备安全区及现有外边距。头像与昵称/等级形成一组，余额成为主要经营数字，评价为次级指标；稳定两行对齐，先为长金额分配空间，不横向压扁整卡。底栏保持招募、车辆、抢单、地图、账单；仅抢单黄底两字，其他入口为图标与名称，不加状态小字。站点仍在地图右上、定位仍在右下。

### 选路与配送

内容顺序为商家→目的地、餐品与需求、路线比较、主操作。三条路线对齐预计时间与餐损风险；选中态同时用描边和文字识别，不能只靠颜色。出发配送为单一主操作，返回接单为次操作。配送中突出当前阶段、剩余时间与进度，沿用真实字段；取餐中倒计时在原位置更新。设计采用更大正文，若纵向空间不足可增加面板高度；以地图不遮挡骑手与取送位置为复验条件，不先承诺地图面积增加。

### 交付与结算

交付要求单独强调顾客留言与两种原有选择，不能增加关闭跳过。结算以本单实际收入为最大数字，下方显示原有构成/扣减说明、评价、经验和最终余额，延续“已到账”及确认继续，不新增领取奖励步骤。短屏只滚动明细，主操作在安全区内可见。

### 车辆

已有侧视车图成为主视觉；车型名称与D/D+徽章配对，下方比较现车与下一档速度、载重、收入倍率。升级价格¥200、余额不足、已拥有/达上限等状态仍来自原有规则。地图顶视80×128设计单位保持。

### 账单

12项全部保留，用三组表达：

1. 钱包：钱包余额。
2. 今日：今日收入、今日订单数、今日好评、在线时长、配送里程、准时率、超时、差评。
3. 累计：累计配送费、累计完成订单、单日最高订单数。

组内采用左标签、右数值，今日收入与钱包余额优先突出，减少12张同权重小卡。日期、历史“≥”下限及未知“—”按现有字段显示，不补造统计。

### 大厅默认处理

保留手机外框、10单无分页、刷新次数及完整决策字段。餐图/餐名与预计收入为第一层，商家→目的地为第二层，时长/里程与必要标签为第三层；接单按钮与文字留出独立空间。按较大字号增加卡片高度，不以缩小文字换取每屏多显示订单。去仿手机框只属于C。

## 视觉与尺寸目标

- 保留现有主黄 `#FFC52D`、白色卡片、米白地图底色。建议正文 `#302B20`，辅助字收深至 `#64695F`，分隔线 `#E3E2D8`；路线候选棕 `#795020`，先按现有路线配色复验后再确定是否替换。
- 最终手机显示目标：正文15–16 CSS px，辅助13–14 CSS px，金额24–28 CSS px；地图版权与比例尺按地图语境单独处理，不删去来源。它们是设计目标，非已测结果。
- 关键触摸区域目标至少44×44 CSS px，图形允许更小但触摸区不能互相重叠；真实单位需结合Cocos缩放与安全区换算。
- 卡片圆角与按钮圆角分别统一，不追求所有组件相同。白色顶卡继续无阴影；正式图标由用户提供。示意中地图骑手标记仅表位置，正式载具仍用已有顶视图。
