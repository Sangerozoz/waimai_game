# M1接单大厅与当前订单交互方案

2026-10-29；游戏策划；PM已采纳的有界方案，待开发实现，不代表功能已完成。
输入：用户最新反馈、OrderPhone、MapSample.renderPanel/navigation/rebuildLayout、OrderBook、CityMap。
范围：现有M1单单与弹窗；不接M2新时钟/手动取送，不实现独立页面或真实骑手转单市场。

## 源码确认

- navigation当前中央红圆112设计单位，文字44；有单时中央与车辆入口禁用，地图/账单仍可用。
- openPhone只允许idle；renderPanel只要active就绘制订单卡，没有独立收起状态。
- routes底部“返回接单”实际调用cancel清除active；“出发配送”调用depart；两者不能当作普通关闭复用。
- 切路线调用setRoutes但未请求fit；rebuildLayout先setRoutes(...,true)后locate(true)，会覆盖路线总览。
- focusRoute虽计算路线包围尺寸，镜头中心仍放riderPoint而非包围中心；较长路线可能出屏。
- setRoutes会把骑手位置重设为路线起点；running恢复展示不可重置真实riderPose。
- DeliveryOffer目前只有food字符串（含“· N份”）、weightKg、type、fragility、demand等，无来源、独立份数或自由买家备注字段。
- list提供deadlineSeconds，accept根据合法路线中最快时间确定active.deadlineSeconds；展示需核对两者同口径，不能拿预计时长冒充期限。
- M1取餐为自动停2秒，普通送达自动结算，门口需求走选择弹窗；本轮保持该业务。

## PM已确定的导航方案

保留底部菜单；中央idle文案“抢单”、active短文案“订单”，语义统一为返回当前订单，卡片标题可写“当前订单”。
有单不另开大厅，保持M1单单；关闭卡只收起，中央恢复对应阶段卡。
中央红圆按当前112×1.3=145.6设计单位，图形与触控根一起增大，仍为圆；两字大字居中。
底栏和相邻车辆/地图位置按145.6圆避让，留≥12设计单位；安全区、按压态和禁用规则不被倍率覆盖。
招募持续灰且无事件；站点未上线继续原禁用。车辆入口有单可查看，换车必须在OrderBook业务层继续拒绝。
其他功能弹窗关闭后恢复原卡显隐、所选路线及对应业务阶段；不cancel/finish/refresh候选。

## 手机大厅与单卡

- 用外壳后层偏移(6,-8)、深色侧面、浅色倒角/高光、屏幕内凹和侧键形成可见机身厚度，控制在现有安全区内。
- 蓝色为屏幕顶部连续区域，从时间/电池/刘海所在状态区延伸到大厅标题；去掉状态区与AppHeader间纸白断层。
- 保留时间09:41为装饰状态栏，不声称是送达时间或设备实时值；电池/刘海使用高对比色，关闭按钮独立触控。
- 卡片顺序固定如下，长文本增加卡高，不跨层覆盖；整列表滚动，按钮在各自卡内。

| 顺序 | 内容 | 数据与展示 |
| --- | --- | --- |
| 1 | N分钟内送达 | deadlineSeconds向上取整到分钟；转单在分钟前加“转单”标识；加急标签独立 |
| 2 | 菜品、N份 | 真实food与quantity语义，餐图作为此行配图 |
| 3 | 重量 | offer.weightKg，kg单位 |
| 4 | 起点、终点 | POI真实名称，取/送两行，支持换行 |
| 5 | km | pickupMetres+deliveryMetres，即当前位置→商家→顾客全程，保留1位小数 |
| 6 | 买家备注（有才显示） | 见下方数据规则；空值整行省略 |
| 7 | 金额 | 沿用estimatedIncomeCents，标“预计¥”；已接卡费用采用同口径，勿把feeCents当实际到账 |
| 8 | 操作 | 普通黄“抢单”；转单绿“接受转单”；均调用同一accept(id)获取该单 |

“分钟内送达”是M1游戏时限，不是现实墙钟倒计时；预计路线时长保留在路线卡比较。
候选与接取后的期限应由同一个合法最快路线口径产生；若list与accept不一致，统一预览计算，不改原截止公式。
当前固定普通最快+5分钟、加急最快；不借转单加价、减时或生成历史已消耗时长。

## 已接卡、路线与底部操作

- 头部先“限N分钟内送达”；出发后在同一头部显示现有剩余时限/晚到状态，不新增一行重复时限。
- 下方依序：起点终点→费用→菜品/份数→重量→注意事项（加急/怕洒等真实标签）→买家备注（有才显示）→路线选择。
- 全卡内容采用单一纵向滚动区；底部固定操作区只放一个“去取餐”，内容底部预留按钮高度+16，避免长地址遮挡。
- routes点击“去取餐”只调用既有depart；不新增确认取餐/确认普通交付。移除“返回接单”“出发配送”及底部重复门口/期限文字。
- routes显示实际合法路线，最多三条；若现有去重只剩1/2条，按实际显示，不复制假路线凑三条。
- 路线卡维持快捷/主干/平稳差异，展示时间、km、准时/晚到、餐损风险；选中卡与地图同色突出。
- 首次接单与每次切路线，总览所有可选路线的完整几何（含当前位置→取餐→送达），选中线加粗，其余弱化，可比较真实绕行。
- 镜头以全部路线包围中心适配可见地图矩形，扣除头部、订单卡、底栏、边缘留白；不能只算缩放后仍居中骑手。
- 自动规划总览允许缩放低于现MIN_SCALE（比例尺数值可大于100m）以容下全程；只作用自动规划视图，手动缩放仍10–100m、定位仍30m，禁止扩大派单范围。
- 默认路线总览不受renderPanel或rebuildLayout末尾locate覆盖；手动拖缩后保留用户镜头，显式切路线才重新总览。
- 地图上的真骑手始终来自riderPose；纯展示重建/切线不得重置进度或瞬移到起点。
- “去取餐”只用于routes；running用进度，arrived用既有需求处理，done用现有回执/继续接单，避免运行中再次depart。

## 状态与返回矩阵

| 业务态 | 中央入口 | 订单卡/动作 | 地图与关闭后行为 |
| --- | --- | --- | --- |
| idle | 抢单→大厅 | 无活动卡；大厅可关闭 | 当前骑手地图；关大厅不改候选/游标/刷新次数 |
| routes | 订单→打开卡 | 期限/详情/合法路线；单个去取餐 | 首次/切线总览；X收起卡保持选线、active和镜头，再点中央找回 |
| running | 订单→打开卡 | 真实取/送进度、剩余时限；无再次出发 | 默认骑手跟随，手动可接管；收卡继续原M1行驶，不暂停/取消/清档 |
| arrived | 订单→交付处理 | 有需求显示处理入口；无需求按原自动结算到done | 骑手在终点；原需求弹窗两种选择保留，收卡不替用户回答 |
| done | 订单→已完成卡 | 收入与回执、继续接单 | 终点地图；卡X只收起，不finish；继续接单明确finish后开大厅 |
| 任一态打开车辆/地图/账单 | 弹窗在上层 | 记录来源卡显示状态、滚动位置、选线与镜头模式 | 关闭非配送弹窗恢复该来源；不cancel/finish/重抽/定位重置 |

- arrived的强制需求弹窗不允许遮罩代答；若允许X则只收起需求与卡，中央再次打开同一待答需求，不可因此推进时间或结算。
- done“结算详情”是配送回执；回执X/遮罩沿用finish+save并重建干净首页，不能恢复残旧底卡。此为明确完成业务动作，需与订单卡X及非配送弹窗关闭区分。
- 从原已展开卡进子弹窗，返回仍展开且滚动位置恢复；从收起卡进子弹窗，返回仍收起，中央入口始终可找回。
- running在子弹窗期间沿用当前前台推进，返回按最新业务状态呈现；不能恢复过期running视图覆盖已到达/done。
- 业务推进至arrived时保留待处理通知，避免无故销毁用户正在看的非配送弹窗；关闭后展示待处理卡/入口。
- 历史paused仅兼容展示按当前进度恢复，不新增暂停按钮或更改既有恢复业务。
- 关闭订单卡和非配送弹窗返回只改viewState，不调用cancel/finish/refresh；中央统一以“订单”返回当前单。
- 横竖/安全区重建保存上述展示状态；刷新/重启从有效active重新打开当前阶段卡即可，不要求持久化纯UI收起状态。

## 转单、份数与备注数据语义

- source建议可选枚举direct/transfer；与type normal/urgent正交，新单可为转单普通或转单加急，均无真实平台/骑手身份。
- PM确定新生成非首单来源约20%转单，首单固定direct且保留原普通首单；10单大厅平均约2张而非每批硬配2张，不抢占餐品类别/区域名额。
- 来源按新订单ID与固定source-profile稳定分配约20%；不额外消费食物、餐损等随机流，不声称安全随机。
- 来源生成后随候选、active、回执所需信息保存；重开/刷新视图不重抽，旧无source按direct，旧候选/活动不回填“转单”。
- 接受转单无追加费、押金、转出、抢他人订单、额外倒计时或市场系统；仅本地订单来源与对应文案/按钮色。
- quantity建议新增可选正整数，新生成同时写入food展示与quantity，重量仍为已算好的整单weightKg，不再次乘份数。
- 旧档仅在food匹配已知餐名+严格“· N份”格式时提取份数；不可解析显示“份数未提供”，保留原food字符串与重量，不猜“1份”。
- buyerNote建议可选字符串且有长度上限，只有真实生成/恢复的数据才能展示；当前demand=door可由共享映射展示“放门口，别敲门”。
- 风险、加急、预计超时放“注意事项”，不得写成买家留言；无自由备注来源时不生成虚构留言，demand=none省略备注。
- optional字段必须进入严格存档校验，坏枚举/非法份数拒绝；旧字段缺省合法，不能因此放宽旧活动金额/结果校验。
- 约20%本地来源、短“订单”入口、份数回退与已有需求映射已由PM确定，无需另等设计批准；若扩展真实转单剩余期限、额外费用或自由留言生成规则，再由PM收集规则。

## 交接验收

1. 新旧档idle/routes/running/arrived/done：关闭卡再找回、子弹窗往返、resize重建不改订单/路线/余额/游标。
2. 连点抢单/接受转单只获同一单；单单限制仍由业务守住；有单看车可行，换车依旧拒绝。
3. 三路线（或真实1/2条）完整入镜、线型差异可见，切线不重抽风险，去取餐只执行一次既有出发。
4. 期限与接取冻结值同口径；份数/整单重量/预计金额无误；旧无新字段能恢复且不生成伪备注。
5. 长中文、长地址、窄短屏与安全区：头部蓝色连贯、机身厚度、卡片不遮挡、单底部按钮、145.6圆及相邻入口可触。
6. 本文为已采纳方案，尚未实现；开发/测试在隔离模型与样板验证，用户正式页面/存档操作和最终手感仍由PM安排用户验收。
