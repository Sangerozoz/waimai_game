# 县城地图实现：研究结论与生产决策依据

2026-11-05。用户要求停止反复失败，认真研究游戏地图实现方法。本轮仅调研与复盘；没有生图、改业务、改原路、实施新路线、构建或运行游戏测试。

## 结论先行

**本项目适合“原地图数据为唯一几何依据，固定机位，分层场景，分块加载”的地图架构；美术资产如何稳定制作仍是未解决的前置条件。不能以架构可行代替画面达标承诺。**

更推荐评估“统一制作的可编辑3D源资产，在统一相机/光照下离线渲染成2D素材，Cocos固定视角显示”的资产管线。它服务于2D游戏，不要求改成自由旋转3D游戏。理由是本项目不需要自由旋转、拆建或动态光照，却需要一致的方向、比例、阴影和可重新导出的清晰素材。若已有合格手绘分层资产，直接2D同样成立；若没有可用模型/分层源文件，仅靠提示词独立生图，当前证据不足以批准量产。实时3D保留为资产条件成立后的备选，不能通过再写一轮程序楼证明美术成熟。

本结论是结合项目证据与官方能力作出的建议，尚未得到新样板验证或用户批准切换。不能承诺“这次一定成功”或凭文档确定工期。

## 二、成熟方法能支持哪些结论

1. **2D也需要明确空间与图层。** Factorio官方铁路制作记录说明，增加斜俯视细节后交叉处必须拆层；凭眼睛改一个接头可能破坏其他接头，最终建立源场景及自动导出。它支持可编辑源与统一导出流程，不意味着照搬该游戏引擎或风格。[官方FFF163](https://factorio.com/blog/post/fff-163)
2. **精细图片会带来真实资源成本。** Factorio官方讨论过图集、分离阴影、mipmap及显存压力。分块与图集是运行组织，不增加原图细节，也不会自动解决遮挡。[官方FFF227](https://factorio.com/blog/post/fff-227)
3. **固定正交相机可统一尺寸与投影。** Blender官方说明正交相机平行线不汇聚、物体尺寸不随距离变化；这使统一模型批量输出成为可控来源。它不保证模型材质质量，也不证明本团队已经拥有适用模型。[Blender相机](https://docs.blender.org/manual/en/3.6/render/cameras.html)
4. **现有引擎具备基本能力。** Cocos 3.8支持正交相机、程序Mesh和模型渲染；因此没有证据表明必须换引擎。道路连接处理、层级、加载、素材制作仍属项目工作。[相机](https://docs.cocos.com/creator/3.8/manual/en/editor/components/camera-component.html)、[程序Mesh](https://docs.cocos.com/creator/3.8/manual/en/asset/model/scripting-mesh.html)
5. **编辑器可协助摆场景，但不能创造合格美术。** Tiled可使用任意位置对象、折线和多边形，不要求把原道路改成棋盘格。是否引入要看是否比现有坐标JSON编辑更省工；不把换工具作为解决方案。[Tiled对象层](https://doc.mapeditor.org/en/stable/manual/objects/)

更完整的逐项官方链接、版本兼容与能力限制见[一手来源核查](primary-source-findings.md)。来源中的成功案例只能证明方法存在，不能证明一人加AI可在相同预算实现同等质量。

## 三、适合本项目的具体结构

- **逻辑地图保留：** 原节点、边、道路ID、取送点关联、蓝框配送限制继续使用；美术区块卸载时不卸载配送逻辑。
- **地面确定性制作：** 同一份原中心线、宽度和连接关系，生成路面、路沿、路口；河岸与桥梁单独处理。中心线不是完整路面，道路求交/并合、弯道及桥头仍需工程实现，不能只加粗几条线宣告完成。
- **可建设地块：** 道路面、人行道、水系扣除后形成空间，安排楼、庭院、停车、树池、设施。源路有断头或跨河/高架时，不把每个空隙都当闭合街区，也不自动接通所有近邻线。
- **资产层：** 楼体、树与庭院组合保留完整对象和唯一归属。每件有接地点、占地、入口朝向、阴影和必要遮挡片。门应朝临街侧；不能将斜俯视PNG随意旋转、拉伸，适配不了的楼换模块或重新制作。
- **通行可读性：** 沿已确认60–65度高机位、通常6–10m退距与少量穿帮容忍，检查骑手可见通道。退距是方向，不是已有每栋满足的事实；透明抠图/脚点排序也不能自动解决所有凹形建筑和桥的遮挡。
- **显示分块：** 在统一世界场景确定后按可视区域组织地面及资源，跨块建筑保留完整归属/引用。显示块数量是技术组织，与用户审阅25张美术生产图是不同概念，不擅自扩大生产队列，也不靠切碎/放大25图冒充新细节。

这仍属“原路＋场景对象”路线。与旧尝试的实质区别只能来自可编辑资产源、统一导出、完整地块设计和复现证据；如果这些没有落实，就没有理由再次开做。

## 四、为什么不推荐以现有AI图反建导航

若一开始有一张几何自洽、人工整理完成的权威地图，沿它描路再做导航是可行的。现有25图不是这个前提：区内有断路，区间有不同道路/路口，遮挡下也没有唯一正确连接。反建仍要人工确定通路、重新关联取送点、跨区拼接和距离验证，且图片的近景分辨率不会变好。不是绝对做不到，而是当前项目需付出第二次地图工程，仍不消除最主要风险；还需用户批准改原路。

“把原路画在现有整图上”也不推荐：会盖过楼顶/河岸，留下旧路残影；需要大量人工重画地面和重排建筑。不能把直接覆盖当零成本复用25图。

## 五、先确认资产来源，再考虑验证，避免第四次无边界试错

**第一关：资产可交付性，当前未通过。** 必须找到可用的统一风格源模型/分层美术，或确认能承担定向制作与修整的人力。评估许可、风格、屋顶/立面细节、方向、源文件与批量导出。现阶段不推荐具体购买项，也未执行采购；AI用于概念/纹理/候选图可以，但没有证据允许承诺自动生成生产级一致模型或精灵。若没有合格资产与修整能力，应把缺口明确为美术人力/预算问题，而非继续调提示词或换引擎。

**第二关：有代表性且有边界的工程验证，尚未执行。** 选择一处真实路口与弯道、含河桥位置，以及两个相邻但形状/功能不同的地块；范围由覆盖这些难点决定，不机械追求某个米数。使用相同世界坐标，确认整路可见、骑手落在路上、出入口正确、跨块不切楼。固定同一机位与既定近景，并与原认可画风对照。不能只提交一张没有骑手或没有接头的漂亮图。

**第三关：第二块复现与资源测量，尚未执行。** 第二个不同地块必须依照同一规则交付，登记美术制作/修整/布局/接入工时和返工。性能检查需按后续明确授权组织，记录设备、帧时、内存、跨块卡顿。第一块漂亮或构建Finished都不算量产证明。

任一关失败就停在具体缺口，不扩县、不自动换下一种方法、不再批量产图；先报告失败属于资产、坐标、遮挡、清晰度还是性能，以及是否有可证实的补救条件。用户无需承担逐张寻找技术错误的主要责任。

## 六、清晰度与成本结论

本地25区manifest的名义像素密度约1.12～1.18像素/投影米（不是图中道路的实测配准密度）。若某方向仅显示35投影米，则对应约39～42原生像素；屏幕显示尺寸还须结合实际投影和视口计算。这个量级说明：1254整区图不可能仅靠拼接、插值或加图集获得极近景细节。离线渲染分辨率/精灵最大显示像素必须从真实视口反算；3D仍需合格模型和纹理。

美术生产、地图工程和技术美术是不同职责，可以兼任但无法省掉。没有第一关和第二块的实际工时，不给“几天完成全县”的数字。现有原路/业务/分区数据可保留；25张原图保留审阅与风格规划价值，具体可回收多少建筑素材尚未核实，不承诺全部变成可用地块。
