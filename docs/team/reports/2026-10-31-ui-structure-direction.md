# UI-DIRECTION-1031-P：整屏结构方向

2026-10-31；游戏策划；仅供PM与用户讨论，不实施、不构成用户批准。
用户问题：界面不像游戏，简陋、粗糙。用户现已允许重排页面，比较地图首页与人物＋车辆＋街区大厅；此处提供两方向的信息架构。
本轮仅静态阅读文档/源码，未打开游戏、测试、typecheck或渲染；尚不能断言当前实际画面的具体视觉缺陷。

## 现状与不可回退边界

- 当前M2进行中；单单手动取送、点击加速、到店/结算事件、暂停取消及独立车辆页已实现，均待阶段集中测试。
- 首页保留地图、真实钱包/评价/等级与导航；接单后隐藏底栏、活动订单卡无X，不能套回早期收卡方案。
- 取餐前免费取消；取餐后白Ⅱ暂停，继续/取消配送；取消保实际位置、不发本单奖励、不另扣钱评价。
- 当前大厅为手机机身容器+真实10单列表；当前配送采用底部贴边sheet；车辆已是独立收藏宫格、全部/我的筛选和详情确认。
- 真实俯视路网是操作地图；侧45车辆图服务展示，不能拿地区插画替换可玩路网或改成斜视手动驾驶。
- 图5日系青春都市动漫厚涂是唯一美术方向：暖白/炭灰、外卖橙、香槟金主操作；转单绿、风险红、禁用灰。
- 默认安全区内+16CSSpx；配送sheet背景左右底贴屏、内容16、按钮底safe+24；保持现菜单含义和按钮动作。
- 当前只有县城1个可玩地区；人物/地标/地区候选图不等于可用素材或新地区解锁。

## 用户已允许比较的两种整屏组织方式

| 方向 | 首页分区与主视觉 | 接单/配送/车辆职责 | 价值与取舍 |
| --- | --- | --- | --- |
| A 地图首页 | 上12%身份/钱包评价；中73%真实道路与当前骑手；下15%既有导航，中央抢单 | 手机选单→地图专注配送；车辆独立宫格 | 强调人在路上、当前位置可感知；需要明显改善路网/建筑/骑手层次，不能仅放大空白地图 |
| B 人物＋车辆＋街区大厅 | 上12%身份/钱包评价；中约60%主角与当前车、后景街区；下约13%当前车/出勤信息，底15%既有导航与抢单 | 手机选单后切真实地图；配送结束可返回街区大厅；车辆仍独立宫格 | 主角与车形成更强游戏身份，首页更像游戏入口；增加大厅→地图切换，需要完整背景与人物构图 |

本轮推荐B作为视觉对照的主候选，A作为操作连续性更强的保守对照；用户尚未最终选择，不改实现。
理由：用户明确觉得现状缺少游戏感，B能在首页直接呈现“我是谁、骑什么、在哪出勤”，同时保留真实路网用于实际配送。
B大厅只能展示当前真实人物/当前选中车/县城街区；不加入NPC收益、体力、任务领奖、假营业店铺入口或新地区解锁。
B中人物与车为同一出勤场景，避免两张立绘并排贴卡；主角偏左、车辆偏右前景、街区后退，中央抢单与人物视线/构图呼应。
B下部真实信息不够时直接保留场景留白，不用未实现功能填满；头像/经验与全身人物用途不同，避免重复大面积身份文案。
两方向共用同一手机、配送及车辆信息架构；比较的核心是首页舞台及返回场景，不重复制作两套完整业务。

| 屏幕 | 分区 | 信息与视觉焦点 |
| --- | --- | --- |
| 首页 | 顶约12%身份摘要 | 左头像/短Lv/真实经验；右钱包与评价。主角身份是一组，经济是一组，不把所有字做同等字号 |
| 首页 | 中约73%地图舞台 | 真实骑手/当前车落在可辨道路上，建筑形成街区层次；地图第一焦点为骑手，地点标签与控件退为次级 |
| 首页 | 底约15%导航 | 继续现有向两边展开菜单；中央暖橙亮面圆“抢单”唯一强主操作；车辆/地图/账单次级，招募灰 |
| 接单大厅 | 机身上约16% | 状态栏/刘海与大厅标题融合；关闭在固定角位，刷新为次级按钮，首单/刷新说明压为一行 |
| 接单大厅 | 中约76%任务列表 | 紧凑订单卡：期限顶→食品行（图+菜名份数/重量属性；右费用+km）→取送地址横行→有值备注→接单按钮 |
| 接单大厅 | 底约8%机身收边 | 页数/滑动提示与HomeIndicator低对比，不再与订单主操作争色；列表可滚动，普通单卡自身不嵌套滚动 |
| 配送规划 | 上约55–62%真实地图 | 全路线入镜、蓝黄绿真实方案差异；HUD不遮端点，小取/送卡与路径相连；禁止用满屏经营点替代重点 |
| 配送规划 | 下约38–45%任务sheet | 期限+紧凑订单信息；横向最多3路线；小红取消在左、大金“去取餐”在右，固定按钮底边 |
| 配送执行 | 地图尽可能扩大 | 骑手、当前目标与选中路径成为第一焦点；可压缩已知静态详情，保真实剩余时间/任务阶段和现有加速操作位置 |
| 配送执行 | 底部阶段操作 | 去店→取餐→取餐进度→去配送→点击加速；每阶段一个强动作，取消/暂停仍遵循现阶段规则，不平铺全部按钮 |
| 结算 | 地图背景+单一结果面板 | 本单收益最大；一行准时/餐损/备注，真实收益影响、评价/经验；继续接单主、返回首页次，上下布局与X首页保持 |

配送执行静态详情折叠仅是提案：不隐藏必要备注/阶段动作、不新增订单卡X；若影响当前按钮位置，由PM明确取舍后实施。
正常订单+三路线须能在短屏读完主要信息；长异常地址/备注才滚动中间内容，期限和操作固定，不能以整体缩小字体换空间。

## 车辆页：既有宫格继续，展示层级更明确

- 顶约14%：返回、当前车名称/档位、真实余额；只保留一行使用状态，避免与宫格重复大幅展示。
- 次约8%：全部车辆/我的车辆；沿用现筛选，不新增碎片、战力、星级或假养成条。
- 主约78%：以侧45车辆插画构成收藏宫格；每格图为第一焦点，档位/名称第二，真实数量/使用/未开放状态第三。
- 沿用现“每格≥100CSSpx时3列，否则2列”，不为统一三列缩到无法辨车；图统一基线、占框比例和安全边。
- 详情是看属性/价格/条件与确认购买/选择/升级的唯一地方；宫格不铺多行速度/载重/所有价格。
- 车型从低到高有轮廓/体量变化，当前使用与已拥有有真实标记；高档资源可看不等于可买或可用。
- 活动中只读看车，不因页面改造开放购买/换车；返回保持当前配送业务状态。以上行为已有，插画舞台化为提案。

## “像游戏”的具体组织标准

1. 一屏一个主视觉：地图骑手、订单食品/费用、车库车辆；避免每块都做同尺寸白框与同强度金按钮。
2. 层级统一：背景地图/纸面→信息卡→可按按钮→关键事件；主操作香槟金/橙、次操作炭灰细金边，绿红只承担来源/状态语义。
3. 地图须形成可辨的道路—建筑—骑手层次，地标是少量环境识别点；素材未处理好前不把候选人物/地标硬贴满地图。
4. 用既有动作塑造反馈：取餐进度填充、车辆真实加速速度线、到店/结算音效；不加用户否定的按钮火焰，也不捏造奖励特效。
5. 重复组件共享尺寸/字体/边距/材质；页面差异来自用途与主视觉，不是各自一套边框。信息先后顺序由阶段决定。
6. 保持真实数据：未开放灰禁用、不能把设计资产当经营收益；收到原图、接入、阶段测试、用户接受分别记录。
