## 2. 产品文案与产品定义

### 2.1 可用于说明当前版本的文案

**在小城街巷里开启你的外卖生活。挑选订单与路线，到店取餐，点击加快行程，一单单赚取收入，升级或购置自己的电动车。**

这段描述对应当前县城单单版本；当前素材与功能仍有待测、待体验项目，不作为发行承诺。

### 2.2 完整产品愿景文案

**从一辆旧电动车起步，把小城里的每一单送好。规划顺路订单，安排取送与补给，逐步招募骑手、建设站点，走向更大的城市，收藏属于自己的车队。**

这是完整V2目标，包含尚未实现的多单、补给、经营和城市成长，不能当成当前版本全部可玩内容。

### 2.3 已制定的产品骨架

| 项目 | 既定方向 |
| --- | --- |
| 类型 | 竖屏外卖模拟经营，结合点击参与、轻策略与收集成长 |
| 地图 | 二维俯视真实路网、虚构地名，车辆沿道路自动移动 |
| 操作 | 玩家选单、选路、到点操作；点击加快现实等待，不点也能完成 |
| 策略 | 顺路与绕路、承诺时限、餐损风险、逐段载重，后续加入体力补给 |
| 成长 | 县城主动配送 → 骑手/车辆/站点经营 → 城市扩张 → 国际收藏与强化 |
| 美术 | 图5“日系青春都市动漫厚涂”；真实地图结构上做分层材质与装饰 |
| 技术 | Cocos Creator 3.8.8、TypeScript、Web Mobile；现有地图工程继续迭代 |
| 首版不做 | 摇杆驾驶、现实GPS移动、途中接新单、车辆损耗维修、多条生理数值、NPC逐个吃喝 |

完整目标循环：**大厅接1–3单 → 预览路线/时限/载重/体力 → 安排停靠 → 自动行驶并可点击加速 → 到点取送/补给 → 逐单结算 → 成长经营。**

当前实际循环：**大厅接1单 → 选路线 → 去取餐 → 到店点击取餐 → 2秒服务 → 点击去配送 → 到顾客自动遵从既有交付要求并结算 → 继续接单/返回首页。** 当前不再要求顾客端另点一次“送达”或回答放门口弹窗。

## 3. 核心规则与数值：哪些是既定目标

### 3.1 当前基础与长期约束

- 新档初始¥100、评价80、经验0、免费D车、站点1；每完成一单获得10经验。首个等级门槛50经验。
- 经验收入倍率目标为 `min(1.6, 1 + 0.03 × (Lv − 1))`。经验等级、车辆档位、骑手档位、站点等级分别管理。
- 县城基础配送费¥15–25；D车12km/h、载重5kg；原车D升D+¥200，D+速度13.2km/h、载重8kg、收入倍率1.12。
- 每日2次免费手动刷新；正常完成补候选不消耗该额度。广告能力尚未接入，普通接单与免费恢复不能依赖广告。
- 超时仍可完成，按评价与收入规则处理，不额外强制罚款。餐损每单最多一次折扣，不按点击或帧数反复抽取。
- 钱用整数分；收入、经验、回执、里程与保存重试不能重复入账。迁移保留已有进度，未知未来存档版本写保护。

这些规则有历史设计或实现依据，但不表示当前全部边界已经集中测试。

### 3.4 未来阶段的数值候选，仍需验证

- **M3多单：** 最多3单/6个必要任务；先取后送，按每段实际携带重量校验；同店容量允许才合并服务。10个稳定候选槽位不能靠反复接取/撤回免费换单。
- **M4体力：** 最大100，行驶2点/km，每次实际取餐服务1点、每单交付1点。水¥2恢复20点，饭¥5恢复60点；无单免费休息20现实秒回满，活动中原地休息10现实秒回20点并消耗10游戏分钟。这些是首轮候选参数，未接入当前玩法。
- **M5经营：** 骑手各档招募价¥800/1500/2700/4900/8800/16000/29000/95000/130000/170000；升档付差价。无工资，车无维修费。NPC按真实时间计息，不给玩家经验或城市解锁单数。
- **被动限制：** 正常在线被动累计不超过当日主动配送费的7/3；首单前半速，离线/零主动半速最多8小时、整次领取最多参考平均单收入×500。费率变化只影响之后区间，封顶截额不追补，跨日不重复套上限。
- **M6/M7隐藏：** 一线满足资格后，车辆与骑手线索每单各独立5%，各累计3/6/9条开放S/SS/SSS资格；M6开始保存，站点5与国际后兑现。资格与资产实例分别管理。
- **SSS强化：** 每实例1–30级，收入每级增量1%、车速每级增量0.5%；30级为1.29/1.145。报价使用固定参考基准，不能靠临时换低档车或降低评价压价。

完整公式及内容分布仍以V2设计和审查为依据。旧数值审计是设计试算，不是当前游戏实际平衡验证；NPC回本、三单乐趣、补给节奏与终局追求仍待对应阶段。

## 7. 下一步顺序（供用户核对，本轮不派工）

1. **先核对本稿的产品方向、现行覆盖规则、阶段位置和优先级。** 有误由PM统一修文档，避免开发同时引用多个互相冲突的旧入口。
2. **汇总当前县城版本的实际体验反馈，明确本轮收尾范围。** 首页样板/商城视觉细节与配送主链分别记问题，不把审美待确认自动写成程序缺陷。
3. **按确认范围交开发收尾。** 保留所有在途工作与用户存档，交付写“已实现，未测试”；若需要试玩，再按用户意愿恢复单一明确入口，不自行重启已关闭服务。
4. **用户明确说“阶段完成”后集中测试。** 优先完整一单、取餐/取消/结算、保存/库存迁移与并发、里程跨日/点击一致性；再覆盖界面适配、音频与设备表现，用户体验验收另记。
5. **M2出口明确后，才细化并推进M3；之后沿M4→M5→M6→M7。** 目标或重要体验取舍若改变，先形成具体方案由用户决定。

本稿未新增总工期、发行日期或未授权功能。原目标首屏≤3秒、低端设备≥30fps仍为待实测性能目标，不作为已达成结论。

## 8. 需要用户核对的重点

- 产品仍以“自动沿路配送＋点击参与＋后续轻策略经营”为主，完整手动驾驶不在当前路线。
- 当前顾客端自动履约结算、配送阶段可无奖励取消，是后续用户决定对原V2的覆盖；若现在意图改变，需要明确改哪条。
- 当前先收好县城与M2出口，再进入三单；商城与首页已有交付不等于经营阶段完成。
- 未来体力、骑手回本与终局数值仍是候选/待体验，不因设计审计通过就视为最终平衡。
- 首页采用真实几何＋分层材质＋允许空地补景；概念图不等于整张地图已经达到同样效果。
