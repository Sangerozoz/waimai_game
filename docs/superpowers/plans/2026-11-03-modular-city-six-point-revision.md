# 二维街角六项修订实施计划

> 执行方式：复用用户已授权的新固定开发与PM。项目约定优先于默认技能的逐改测试、自动提交和重复审批。

**Goal:** 在现有/modular-city/街角内落实六项实际审图反馈。

**Architecture:** 原生完整建筑方向素材负责立面美术；原路网坐标负责地面分区和入口连接；独立地面投影负责统一光影。Cocos2D、数据manifest/layout、内置image_gen。

**Global Constraints:** 不扩全县、不恢复3D/盒子楼、不改变正式产品/路网/存档、不提交/清理、用户说阶段完成才游戏测试。新图未用户验收；新构建状态与视觉验收分开。

## Task 1：保存反馈、生产美术（PM）

- [x] 阅读当前基准、旧engine-v3与已认可首页，逐条记录用户要求和修改方案。
- [ ] 用内置image_gen生成三类楼的左右临街版本，保留透明底、30°斜俯视、左上光；每次完整prompt、源路径与SHA留存。
- [ ] 生成入口砖与种植土地表材质；树池围边以原地面投影几何配合材质制作，保留现有斜俯视树。
- [ ] 对实际产图标注原生UV锚点/可见落地角/正门/高度候选，交付revision-manifest.json和入口选择建议，不通过脚本变造PNG像素。

## Task 2：显示层修订（固定开发）

- [ ] 读取本规格及当前ModularCity.ts，保留旧manifest/layout供回退。
- [ ] 将骑手显示尺寸精确×2，保留轮接地锚点/原路线，不修改车属性。
- [ ] 地面按车道、人行道、建筑门前、树池/种植带分区。道路原节点宽度不改；树池中心跟树脚点一致，补土/草/低围边与少量局部矮栏，保证可见车道净空。
- [ ] 建立统一光向和高度比例的建筑方向投影、树冠投影、杆体投影与接触影；投影先于物件、符合脚点，避免黑色整图斑块或透明矩形。
- [ ] PM素材到齐前先准备数据接口；收到revision-manifest.json后接入新PNG、测量锚点、主门位置和实例方向；不得用平面旋转/翻图顶替。
- [ ] 原8栋实例选择合理临街方向，必要时微调候选摆位及门前连接，不移动源道路或源建筑。

## Task 3：独立构建和事实交接（固定开发→PM）

- [ ] 仅运行build-modular-city.sh所需构建，报告退出码/Finished和实际诊断；不附带测试。
- [ ] 部署当前隔离入口，确认HTTP可达，保留旧版本可回退。
- [ ] 在docs/reviews/modular-city-20261103/implementation-report.md追加每条修改的实现证据与真实限制。
- [ ] PM同步素材README、长期基准和当前交接。当前浏览器自动化被Work设置禁用，未实际看到新画面则明确说明，不能用AI整景充当工程截图。
