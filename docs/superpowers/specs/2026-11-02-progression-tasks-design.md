# 成长目标：存钱提示、前往购买与完成奖励

2026-11-02，PM产品方案审阅稿。用户已确认机制方向；下文提醒方式、任务组织和奖励参数为PM推荐。仅产品资料，不代表已实现，不派开发或测试。

> **已收口到正式V1：** [产品V1](../../product/2026-11-02-delivery-game-product-v1.md)及[参数包](../../balance/2026-11-02-product-v1/parameters.json)现为生产入口，44个任务及具体补给奖励ID已内联至参数包。本文保留推荐来源，下面四组待确认状态已经关闭；初版数值仍需后续阶段测试校正。

## 1. 用户已确认

- 存钱达到可解锁骑手、车辆或地图的条件时，提示玩家前往解锁/购买。
- 实际完成对应目标后，系统额外奖励部分金币或补给品。
- 地图需要支付解锁费，同时满足订单量或团队建设条件。具体门槛组合及费用由PM形成候选，统一审阅。

金币足够是提示条件，实际成功购买/招募/开图才是完成条件。提醒不自动购买，不提前用尚未发放的奖励抵购车费或解锁费。

## 2. 推荐采用的组织方式

采用“阶段成长目标＋首页置顶一个推荐目标”：首页只显示一张简短目标卡，点开可看当前阶段其他目标并切换关注项；玩家可以自由选择投资顺序。后续未开放的目标只预告解锁条件，不催促购买。

比较过的替代方式：严格线性主线更容易引导，但可能逼玩家按固定顺序花钱；全部可买物品同时弹提醒容易淹没地图。本方案在可见目标和经营自由之间取中间方案，不增加第六个底栏入口。

推荐顺序优先解决当前经营需要：新招NPC未配车时先推荐可用车辆；已具备车队时再推荐下一次招募/车型改善；地图目标展示进度，但不强制玩家立即换图。招募奖励不等于赠车，未配车的NPC不能展示假收入。

## 3. 从存钱到领奖

| 状态 | 玩家看到什么 | 操作与结果 |
| --- | --- | --- |
| 资格未到 | 目标、所需地图/骑手名额/经营条件 | 可查看条件，不显示“可购买” |
| 资格已到、钱不够 | 目标、当前余额/费用、还差多少金币、奖励预览 | 可继续亲送或经营；显示实际余额，不用历史累计收入充当可用资金 |
| 钱够但其他条件未到 | “金币已足够”，同时显示尚缺的经营条件 | 地图不能仅凭钱包达标就假显示“可解锁” |
| 全部条件满足 | “可招募／可购买／可解锁”及“前往”入口 | 跳转对应骑手/车辆/地图页面，定位目标；再由玩家确认消费 |
| 实际完成 | “目标完成”及实际奖励 | 成功购买/开图后自动发一次奖励，给简短提示并推荐下一个目标 |

购买前再次读取真实余额、资格、名额及车辆数量上限。中途花掉钱后，目标卡恢复“还差金币”，不能保留过期可购买状态。刚刚获得奖励导致下一个目标达标时，只更新目标卡，不连弹多个购买窗口。

若玩家先买了目标、后才查看任务页，只要购买事实已被任务记录，就正常判定完成，不强制先点击“前往”。起始免费赠送D车不视为一次付费购买。旧存档的具体识别与迁移由后续开发按真实记录处理，本轮不改存档或伪造历史购买。

## 4. 提醒时机与文案

- 首页目标卡持续展示进度；同一目标首次满足条件时给一次轻提示，忽略后保留卡片，不因每次金币变化反复催促。
- 亲送途中只记录可达成状态，不弹购买窗口、不切离当前配送；整批完成或主动取消回首页后重新核对，再提示。主动取消本身不完成成长任务。
- 购买入口展示真实扣款与奖励预览，奖励在成功后发放；不会让玩家误以为购买只需付扣除奖励后的差价。

示例文案（使用当前价格候选）：

- “购买C级电动车：已有260／需要320，还差60金币；完成奖励32金币。”
- “已可购买C级电动车，前往车辆页。”
- “目标完成：购买C级电动车，获得32金币。”
- “城市地图：解锁资金已备齐，经营条件仍差……。”实际UI由条件列表给出真实差额，不显示省略号占位文案。

## 5. 任务范围与奖励候选

推荐只做一次性成长里程碑，同一个存档中：每个招募序号一次、每档车型首次付费购买一次、每张新地图首次解锁一次。普通车型重复买多辆仍允许，但不会反复触发同一首购奖励。此版不增加每日任务、随机奖励或额外任务经验。

| 类型 | 完成条件 | 初版奖励候选 |
| --- | --- | --- |
| 骑手 | 第n名NPC成功招募，n=1…30 | 招募费的10%，四舍五入为整数金币 |
| 车辆 | 十档车型中该档首次付费购买成功 | 实际首购费用的10%，四舍五入为整数金币 |
| 地图 | 第2…5图首次支付解锁费并成功开放 | 新阶段饮品×2＋餐食×1，具体品类随补给表匹配 |

奖励按任务配置固定，消费前即可预览；不按领取时临时配车、余额或属性涨跌浮动。每笔真实消费只推进对应目标，金币增加本身不完成任何购买任务。

现价格候选下：30次招募奖励合计7144金币；十档首购奖励合计1368金币，两类一次性金币共8512。地图奖励合计8份饮品、4份餐食。以上是候选上限，不是玩家开局获得的钱；达成全部对应里程碑才会取得。

示例：首名骑手招募100→奖励10；D车首购150→奖励15；C车首购320→奖励32。购买时必须先有完整费用，奖励到账后才能用于下一个目标。

每个任务以自己的唯一完成记录发一次奖励；购买失败不完成，重复点击或重进页面不再发。目标卡更新与金币/补给到账形成同一次成功结果，不能只显示成功却丢奖励或重复奖励。

## 6. 补给品如何使用

奖励补给品以具体种类和数量保存，放在现有吃喝入口展示“持有×份、使用、购买”。不另做背包格子、负重、合成或过期系统。拥有奖励品时可以选择使用；消耗一份库存代替支付金币，恢复量及动作耗时与同款正常补给一致，不自动吃掉、不自动充值体力。

满体力时不误消耗恢复型补给；免费补给动作仍可能影响未完成订单时限。取消配送不会退回已使用的补给品，未使用的库存继续保留。用户尚未决定后期是否保留便宜补给；本任务方案不提前关闭任何已持有的奖励品。

## 7. 账单、经营进度及经济关系

- 金币奖励单独列“任务奖励”，不冒充配送收入，不给主角配送经验，不计入完成订单数。
- 补给奖励登记品类/数量；使用奖励品的金币支出为0，记录消耗，不再扣一次售价。整趟“配送净赚”只扣本趟实际金币补给支出。
- 是否通过亲送恢复NPC额度另行决定，任务金币和点击领取不能被当作亲送来补额度。
- 新奖励和地图解锁费都要进入联合经济表。旧“首次车队需要再跑15单”的估算不含新奖励/补给/解锁费，不能直接作为本版承诺。

## 8. 地图费用候选与既有门槛衔接

地图付费已由用户确认；推荐费用候选为第二图500、第三图1500、第四图4000、第五图10000金币，共16000。初始县城不付开图费。此表仍是PM候选，不视为已验证的成长时长。

经营条件推荐继续使用总案的“全队累计单量＋适度团队建设”，避免要求全部升满。具体单量/人数/代表车辆与费用一并校准，支付前同时检查；失败不扣费，成功后永久开放，回到已解锁地图不再次付费。开图不迁移或清空资金、车辆、骑手和成长。

地图费用由地图定义提供，任务只读取它，不另抄一套门槛。上述16000是新增开图成本；8512是达成全部30次招募与十档首购才有的任务奖励，不能不看资产路径就直接在旧满车队预算上相减来声称通关成本。
