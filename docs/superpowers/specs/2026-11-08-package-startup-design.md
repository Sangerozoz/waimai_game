# 游戏包压缩与启动优化

用户授权清理历史构建、缓存并降低包体，随后明确图片分辨率过高、可压缩，指定使用TinyPNG。常规实现由PM自行决策；无需重新批准、开worktree、commit或改账号/模型。原始高清素材、地图/路由数据、源UUID与用户存档保留。只发布可核验的运行副本。

## 已确认事实

- 24个历史构建共5,159,503,013逻辑字节。已清除19个停用构建及主工程library/temp，共4,259,390,978字节；保留4个正在使用的构建和1个回退包，其他工程未动。
- 现行游戏210,799,733字节，PNG200,588,751字节；254张PNG/JPG共201,877,408字节。高清源和已裁切派生图都在resources，运行按需加载，不能把总包当首屏流量。
- JS/JSON/HTML/CSS/WASM现行未压缩传输，8,786,146字节可编码为2,103,821 gzip字节（所有文本/wasm总计，非首包声明）；city单文件4,676,885→1,000,589字节。构建还有2000ms splash。
- TinyPNG公网网页首张nav-icons上传返回Something went wrong/INVALID，无结果。官方API凭据缺失，已通过BB安全表单请求，不在聊天、源码或日志保存密钥。

## 选择

优先采用官方TinyPNG逐张压缩运行副本，保留PNG/JPG格式、宽高和alpha边界；先取实际输出和质量指标，再决定是否需要进一步缩小像素。用户批准了压缩，不代表可以打坏已有原图裁切坐标。统一缩放整张atlas会使绝对像素裁切、web pack映射、切片insets失配，因此不做盲目整库缩放。

同期用gzip及正确HTTP缓存降低实际首屏传输，取消运行包固定2秒splash；入口用已有V2，无新存档槽或修改存档。保留可重试/离线错误，不用静态假按钮冒称可操作。暂不同时做资源白名单裁剪：通用包还支持旧入口，删UUID哈希文件会破坏旧分支；先交付能保持完整引用的压缩包。

## 文件与接口

- 新建`delivery-game/scripts/optimize-web-package.py`：读取已构建目录、TinyPNG结果映射，在新目录生成运行包；重新计算被更改文件的内容版本及引用链；保留UUID、图片尺寸、原始city的解码字节与全部业务JS。生成gzip sidecar、体积清单和映射收据。
- 新建`delivery-game/scripts/serve-web.py`并由既有`serve-web.sh`调用：threaded静态服务；Accept-Encoding正确协商gzip，Vary/cache/ETag、HEAD/304匹配；HTML不长期缓存，内容版本资源可缓存；拒绝越界和符号链接逃逸。根目录作为参数，不读应用账号或浏览器进度。
- 证据与TinyPNG下载副本仅在`docs/reviews/2026-11-08-package-startup/`。凭据只从安全文件读取，不回显。

## 验证

先做真正失败的压缩传输测试（gzip解压与原文件一致、协商q=0、不存在gzip时回退、HEAD/304与缓存、路径边界），再实现。对打包器验证引用链、幂等/输入不改、图像尺寸/alpha，以及当前city解码SHA保持。真实TinyPNG结果缺失或失败即明确BLOCKED，不用本地压缩伪称TinyPNG。

用全新headless origin、禁用缓存、1.6Mbps/150ms网络测同包入口和真实新档首页；明确此为隔离新档，不访问用户浏览器或清其进度。记录字节与可操作时间，图片实际显示、透明边缘及其他页面检查独立于资源HTTP200。复用B只读Spec/质量审查。最终部署4182/4196、核包身份，保留当前包回退，并清理新产生的临时构建/缓存。原U01、真机FPS、98%和跨包原档恢复保持原边界。
