# 二维街角：用户六项修订

2026-11-03，新PM接续后的用户实际审阅。授权来源是用户本轮六项要求及既定目标内自主推进约定。保持完整图片Sprite生产方法、原路网、当前隔离入口、正式玩法和存档。旧engine-v3是修改前事实，不是认可母版。

## 用户原话

1. 建筑美观度不够。
2. 地面贴图单一，不符合实际情况。
3. 树木只有树本土，缺少树种植区域的土，草，围栏等。现在的树很生硬的放在地上。
4. 建筑角度，建筑正面朝向有问题，比如最上方那个间距正门朝左，但是道路在他右侧，他等于把侧面靠着马路。
5. 骑手模型太小，至少要放大2倍。
6. 缺少光影，建筑，物体有遮挡关系但没有阴影。

## 处理方案

- 建筑：以已认可00-home-v2.png的清爽暖白立面、层次明确的退台/窗框、蓝灰玻璃和橙色遮阳为参考，重做咖啡餐饮楼、玻璃商办楼、商住楼三类。分别生产正门在画面右侧可见面/左侧可见面的原生方向版本；不能水平翻图、旋转平面Sprite或改道路替代朝向。每实例用最近可通行人行道与立面入口共同决定素材版本和门前连接。
- 地面：保留原路网车道位置和宽度，按实际用途分沥青、人行道、建筑入口细砖、少量种植带，补路缘/排水盖/适量标线；不能全图改一张新纹理。种植带不作为填满所有空白的借口。
- 树：每棵都有明确树池/种植区域。街树用土芯、少量草、低石围边；局部连接种植带用小段矮围栏，不能把每棵树圈成高笼。原生树冠/树干保留，不使用被拒绝的正视v1。树干根点和树池中心一致、树池不压车道。
- 朝向：当前西侧三栋沿街楼优先，随后所有8实例逐一检查入口与相邻道路关系。新PNG注明主门的原生UV位置与frontage方向；入口必须接到真实人行道。选不出合理版本时替换实例选择或局部调整候选摆位，不能更改源路网/原city.json。
- 骑手：在不改镜头、不改道路和车型身份前提下，R01在当前显示尺寸上宽高同比×2（旧画布宽3.2m，新6.4m），轮接地点锚点保留。此为用户要求的表现比例，不是实际车尺寸/碰撞范围/属性变更。
  原engine-v3制作数据按旧fit公式计算的startScale为0.6129619059310744。本轮cameraFocus.fixedScale使用该值，并保留原map/offset；避免新PNG包围盒改变自动取景、抵消屏幕上的骑手两倍尺寸。
- 阴影：统一左上暖光、右下柔和投影。地面方向性投影由建筑占地/高度、树冠和路灯高度产生，叠加根部接触影；不可只把小椭圆加深。PNG内自阴影与整体光源相容。Sprite方法的地面投影不是3D实时光照；跨立面接收和整图细粒度遮挡仍需如实标明。

采用方案：精修原生方向素材＋分区地面＋独立二维投影层。只改数值/颜色不能解决美观和朝向；重返3D超出本轮已定方法，均不采用。
