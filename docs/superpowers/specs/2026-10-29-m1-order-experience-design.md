# M1接单大厅与当前订单交互

来源：用户本轮明确要求放大抢单、立体手机及蓝色整顶、重排订单信息、普通/转单按钮、修复路线遮挡与全程取景、仅保留“去取餐”、可收起卡片并重新找回订单。PM与固定策划讨论后选定下述方案，依既有授权决定常规交互；仍在M1，不开始M2手动取送、多单或独立功能页面。

## 1. 菜单与当前订单

保留现有菜单，主业务状态与视图显隐分开。中央圆按钮无单显示“抢单”打开大厅；有单显示“订单”，语义为当前订单入口，始终可点，不打开新单大厅、不接第二单。

| 业务状态 | 中央入口与订单卡 | 关闭/其他功能返回 |
| --- | --- | --- |
| idle | 抢单→手机大厅 | 关大厅回原地图；不扣刷新 |
| routes | 订单→当前已接卡，展示详情及路线，总览全程 | 卡片X只收起，不cancel；再点订单重开，所选路线不丢 |
| running/旧paused | 订单→当前进度和详情 | 收卡后继续现前台配送；后台仍冻结；重开不重启路程 |
| arrived | 订单→已到达及必要交付操作 | 查看账单等时不遗失交付入口，不强制把用户踢出查看面板；返回订单后可处理需求 |
| done | 订单→未关闭的结算回执 | 回执X/遮罩保持前轮finish+save回干净首页，不残留结算底卡；继续接单则清理完成单再开大厅 |

车辆、地图、账单保持弹窗；关闭时回到原地图及原订单卡显隐，不丢单/取消/换候选/重置所选路线。未上线招募仍灰禁用；有单可以查看车辆，但业务层继续禁止换车升级。以后改独立页面也复用“保留业务状态＋中央当前订单入口”的约定，本轮不提前改成独立页面。

中央红圆视觉与文案整体按现值放大1.3倍，112→145.6设计单位，保持正圆及稳定命中根，安全区横向缩放不压扁；与相邻菜单、订单卡保持明确空隙。卡片底边与中央按钮最高边之间至少12CSS像素，需按实际可见边界量，不能只按菜单背景高度。

## 2. 手机大厅与订单卡

沿用正面直视内容，手机增加明确的后壳厚度、深蓝窄侧边、轮廓亮边、侧键和接触阴影，屏幕内沿有深度；不通过透视缩放使订单文字变形，不拉伸已有PNG。

蓝色从屏幕上缘贯通时间/电池/信号及刘海周围、标题和副标题；暗色刘海、白状态图标，不能出现白色状态栏→蓝条→白条的割裂。内容列表在完整蓝顶下方开始，遮罩与机身边界正确；底部指示条和圆角屏幕可辨。参考本轮art-notes.md。

每张大厅卡按如下纵向顺序：

1. `[转单标签，如有] N分钟内送达`，用真实承诺截止时间，不把预计行驶时长冒充截止。
2. 菜品名称、几份；重量。
3. 取餐地点→送达地点，长名/地址可换行；全程km，口径含当前骑手至取餐再送达，与路线预览一致。
4. 买家备注（确有才显示）。
5. 订单金额：明确显示配送费/基础费用；若展示预计到手另标“预计”，不能把受评价/餐损影响的金额承诺为固定最终收入。
6. 普通来源黄色3D“抢单”；转单来源绿色3D“接受转单”。点按同一可靠接单操作，获得指定订单，一次生效；滚动不得误接。

卡高随内容计算，全部10单可滑动查看及操作，标准720×1280、360×560及安全区长备注均不裁切/重叠。食物图保留但不能破坏信息顺序。不要把风险提示伪造成买家备注。

## 3. 转单及展示数据

转单为本地订单“来源”，与普通/加急履约类型正交，不引入真实玩家市场、主动转出或转单补贴。本轮新候选约20%来源为转单，首单普通；以新单唯一ID稳定分配或等效确定性规则，不额外扰动原餐品/费用/餐损随机流。来源、份数、可选备注在新单生成时确定并随保存保留。

已有候选/活动缺来源字段按普通，不重标/重抽，不改变既定钱、时限、容量、结果；quantity缺失可从既有food尾部N份解析，不可解析诚实显示未提供。现有door需求可对应真实“放门口，别敲门”买家备注；无备注不编造。新可选字段若存在须严格校验，未知来源或非法份数不静默接受。旧存档schema1/2/3与目录v4兼容保持，不借此开M2 schema4。

## 4. 已接卡、路线与去取餐

卡头先显示承诺N分钟内送达，再依次展示取餐/送达地点、订单费用、菜品份数、重量、注意事项、买家备注；截止和门口留言仅在该信息区展示，不再在底部重复。注意事项由加急/易碎等真实条款产生，买家留言单独标识。

信息下为实际可用路线选择，保留快捷/主干/平稳语义与时间、距离、餐损差异；相同几何继续去重，不为凑三条造路线。内容滚动区域底边明确停在固定主操作上方，所有路线可完整看见和点选，操作不能盖内容。点击选择保存对应路线、明显高亮地图几何，其他候选淡化。

接单进入和切换路线都取景完整真实取送全程，按可见地图区域避顶部HUD/卡片/菜单/安全区；检查全部points不只是首尾。不得在focus后又被locate(true)覆盖。自动规划总览允许小于手动100m下限，使长路线也完整显示；比例尺反映真实scale，用户主动定位仍平滑回默认30m，手动缩放原范围保留。

按用户最后说明移除“返回接单”“出发配送”组合，固定主操作仅一个黄色“去取餐”，接入现depart自动配送，不引入M2额外确认。关闭卡片不是取消业务。已运行时显示真实进度，不重复出现可再depart按钮。
