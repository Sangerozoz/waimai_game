## 目标与不变项

还原概念图的都市厚涂画风、完整街区密度、地面层次、统一光照及清楚HUD。继续俯视真实路网，保持寻路、车辆坐标、取送地点、比例尺与拖动/缩放。主角也是骑手；底栏仍骑手、车辆、抢单、地图、账单。没有新增经营点、收益、NPC走动、活动入口或其他城市。

概念中具体房屋/河岸排布和车辆相对大小是生成示意，实施必须回到真实地图几何与尺度。不能把整图贴在地图下方，也不能重新画一张无法寻路的假地图。

## 当前代码基础与实际缺口

`CityMap.ts`已有世界坐标、道路中心线/宽度、区域多边形/水道、建筑轮廓、视野分块、相机缩放与路线/车辆叠加。目前主要由Graphics纯色绘制，局部屋顶为多边形遮罩覆盖，最多选40个可见候选。这是可复用的骨架；单换底色或继续挑少量屋顶，无法得到概念图的完整街区。

主要缺口：可重复使用的路面/人行道/草地/水面材质，屋顶与地块成套表达，按道路和建筑避让的树木/小环境，以及共享HUD皮肤。可见范围较稀疏的建筑数据还需处理，不能靠假业务地点补密度。

## 推荐：真实几何＋可复用材质/图集＋视野分块

| 层 | 依据 | 做法 |
|---|---|---|
| 地面与水域 | 区域多边形、水道 | 在真实边界内铺无缝材质，河岸/草地边缘做窄过渡；同一世界坐标使用连续纹理，移动缩放不换花纹 |
| 道路与人行空间 | 道路中心线、宽度、交叉口 | 路面/路缘/人行道形成层次；交叉口连贯处理，道路标线与斑马线按实际可用位置绘制，不从生成图裁出弯路贴上 |
| 建筑和地块 | 已有真实建筑轮廓与用地区块 | 统一阴影、屋顶基础材质和小型屋面附件，按实际轮廓适配，不用一张大房子反复硬缩；庭院地面补齐街区关系 |
| 环境装饰 | 地块内安全区域 | 树冠、灌木、花坛、少量长椅等用图集复用，位置固定且有道路/建筑/POI排除区；不盖住车辆与路线，不新增可交互商店 |
| 路线/车/地点 | 现有运行时真实状态 | 继续现有蓝/黄/绿语义、真实顶视车、准确地点与定位；视觉材质不反过来修改寻路/计时 |
| HUD | 已确认首页构图 | 头像/等级/余额/评价及底栏、站点/定位独立UI节点，数据动态绘制；优先复用已有图标和母版，按首页补少量无字底板 |

区域缺少建筑数据时，第一轮先核对数据实际覆盖。已有建筑绝不重排；用户本轮已允许在非道路用地内规划明确的非交互院落/绿化及装饰性房屋，不伪称真实建筑或新增经营点，也不修改道路和订单地点。此部分在真实街区样板中明确其范围，再决定扩大。

实现选择建议局部引入可纹理化几何/图集渲染，沿用CityMap协调相机与业务。不要为每棵树/每个屋顶都增加单独大遮罩；近景细节按视野加载，远景降低附件和纹理细节、复用分块结果。具体渲染模块接口由固定开发在实施任务中明确；本轮不强行写入未经验证的API/性能数字。

## 第一批素材拆解（候选，先去重）

1. 地面材质：沥青、人行道/铺砖、院落水泥、草地、水面等少量无缝图，统一图5光色；标线和几何路缘优先引擎绘制。
2. 屋顶：先核已有T01–T03可用局部与现有真实建筑适配；补足灰顶/瓦顶等差异及少量空调/水箱附件，严格正交顶视、统一世界尺度。
3. 环境图集：少量不同树冠、灌木/花坛和必要街区小物件，透明底、左上暖光、接地阴影可复用。首批以一整块街区成立为准，不先堆大量不同建筑。
4. 首页UI：复用已接受人物头像、金币/评价/车辆/地图/账单/定位/站点图标；补首页需要的浅色状态底板、底栏承托和统一按钮边缘，不直接将车库重金属面板铺满首页。
5. 车辆继续真实顶视母版，不使用商城侧45图片或概念图重绘车；所有余额、评价、等级与比例尺保持动态数据。

清单是生产类别，不是已生成或已接入数量；进一步按实际已有文件去重后再定准确批次。

## 实施顺序

1. 固定真实街区样板：取主角附近现有路网和建筑，不改坐标/路线，用新素材一次做齐道路、地块、屋顶、植被及HUD。交付一个完整视野，拖动邻接区仍能接续。
2. 交付可试玩样板供用户实际看图与手感。按用户规则，过程不自动跑测试/回归/渲染矩阵；用户明确“阶段完成”再组织集中测试，审美确认与测试分开。
3. 用户认可样板画面后，再将同一套材质、布置与分块规则扩到当前可玩区域，而不是为每个屏幕生一张背景；接缝/远近细节与缺数据区域在扩展时一并处理。
4. 首版环境可以静态；水面轻动、树影等在场景成立后才评估有限引擎动效，不先制作大量序列帧，也不添加概念图未要求的天气/人群系统。

## 完成应以什么衡量

用户能在真实街区看到完整且统一的道路、地面、屋顶与绿化层次；车辆接地、比例可信；拖动缩放后路面/建筑仍与真实路线和取送点对齐；路线和主操作足够清楚。游戏构建成功只证明产物可生成，不等于这些视觉和操作要求已通过。
