# Cocos H5 躲避障碍小游戏设计

## 目标

用 Cocos Creator 3.8 LTS 和 TypeScript 做一个可在浏览器直接打开的 Web Mobile 小游戏，完整体验“创建项目、写脚本、预览、构建和验证”的流程。第一版不接入外部美术资源，也不连接 TapTap 发布服务。

## 玩法与验收标准

- 游戏画布按移动端竖屏布局显示。
- 玩家控制底部的彩色方块左右移动。
- 障碍物从画布上方持续生成并向下移动。
- 键盘左右方向键和触摸拖动都能控制玩家。
- 每成功躲过一个障碍物，分数增加。
- 玩家与障碍物碰撞后进入结束状态，显示最终分数和重新开始按钮。
- 点击重新开始后，分数、玩家位置和障碍物全部重置。
- 能从 Cocos Creator 预览，并导出可由本地 HTTP 服务打开的 Web Mobile 构建目录。

## 技术方案

使用 Cocos Creator 3.8 LTS，脚本语言为 TypeScript，目标构建平台为 Web Mobile。场景中只使用节点、基础 UI 和颜色，不依赖下载的图片、字体或音频资源。

模块边界如下：

- `GameController`：维护 ready、playing、game-over 三种状态，管理分数、开始和重置流程。
- `PlayerController`：处理键盘和触摸输入，限制玩家在画布范围内移动。
- `ObstacleSpawner`：按时间间隔生成障碍物，推进障碍物移动并回收越界节点。
- `HUD`：显示分数、结束提示和重新开始按钮，并把 UI 事件交给 `GameController`。

游戏状态由 `GameController` 统一持有。输入模块只产生目标位置或移动意图，生成器只负责障碍物生命周期，HUD 不直接修改游戏数据。碰撞检测在游戏控制层或明确的碰撞辅助函数中完成，避免各模块各自维护一套状态。

## 资源与项目结构

项目放在当前仓库的 `cocos-dodge-demo/`。首版只提交 Cocos 项目需要的文本和场景资源，保留引擎生成的必要元数据，不提交本机缓存和临时构建目录。浏览器构建输出放在项目外的临时目录或被 Git 忽略的构建目录中。

## 环境与运行流程

1. 通过 Cocos Dashboard 安装 Cocos Creator 3.8 LTS。
2. 在当前仓库创建并打开 `cocos-dodge-demo` 项目。
3. 在编辑器中配置一个 Web Mobile 主场景。
4. 使用 Codex 添加和修改 TypeScript 脚本，运行 Cocos 预览并修复报错。
5. 从编辑器构建 Web Mobile 版本，并用本地 HTTP 服务打开构建结果。

## 错误处理与验证

- 没有找到 Cocos Creator 时，先报告缺失的安装路径，不生成假构建结果。
- 构建失败时保留日志和源码，先修复首个可定位错误，再重新构建。
- 触摸输入不可用时，键盘输入仍应可用于桌面浏览器验证。
- 验证以浏览器实际操作为主，辅以 TypeScript 类型检查、构建退出码和浏览器控制台错误检查。

## 明确不包含的范围

- 暂不制作正式美术、音效、关卡编辑器或账号系统。
- 暂不接入广告、支付、联网排行榜或 TapTap CLI。
- 暂不生成 Android 安装包；先证明 H5 构建和试玩流程可用。
