# M1界面缺陷修订

来源：用户在项目经理会话2026-10-29明确要求优先修复美术六项问题，并补充底栏文字应「叠在图标内部下方，和图标浑然一体」。本轮属于M1，项目经理按既有授权决定实施细节，不开启M2玩法。

## 用户可见结果

1. 顶部身份、经验、余额和评价保留清楚的信息层级；清除重复的大背景/边框。每个组件只由一套正式视觉渲染，失败占位与成功皮肤不同时显示。安全区与长金额继续可用。
2. 底部五入口直接浮在地图上，不保留整条底座或各入口额外背景板；图标显著放大，文字叠在图标内部下方，作为一个视觉整体。中央抢单优先用现有黄色餐袋图标配内部下沿「抢单」字，比两侧更大更突出；本次明确的图文一体要求覆盖早期中央只保留两字的外观约定。未上线入口仍禁用置灰，整体不挤出安全区。
3. 定位保留足够触控面积，只显示定位图形；去掉外部正方形框、底板和装饰背景。图标资源自身如带底也要绕开，确保不是只删宿主背景。
4. 所有可用按钮提供即时按压/释放反馈；取消、滑动列表、手指移出、禁用、多指和节点销毁都能正确恢复，不改变已有动作次数、拖拽阈值、回调或存档。命中区域本身不缩放，视觉在子层反馈，松开不强制等待动画才能执行动作。
5. 车辆、地图、账单及共用弹窗：标题清楚稳定，取消被压扁的紫色图片装饰；关闭为可见图标按钮，保留失败回退和明确命中范围。
6. 抢单弹窗恢复可识别的手机外形、屏幕边界和顶部结构；10单单列表滚动保持。关闭用图标；列表内抢单按钮在不同宽度下保持圆角/边框厚度一致，不拉扁PNG。动态文字由原生标签显示，不烘焙到图片。

## 实现原则与取舍

优先修正共享渲染组件与实际调用处。已有插画/图标继续使用；根据查明的根因选用按目标尺寸绘制的圆角/边框，或经实际多尺寸截图验证的九宫格。当前方形面板被缩成细长标题的做法不适合继续套用。必要图标可用现有资源的正确裁切或清晰原生图形，无需为几何底板新增生图批次。美术角色给出资产判断后再决定。

按压采用短促收缩与恢复，角色动画报告给出具体参数；静态皮肤与内容在同一视觉根节点，实际触控根节点不变。保持资源缓存、异步失败/关闭保护及节点销毁释放。

## 验收与权限

开发保留修前文件和截图，提供首页、车辆、地图、账单、抢单手机列表的渲染对照。至少覆盖720×1280标准竖屏和一个短/窄视口，以及宽窄按钮的圆角/边框与标题比例。可以用隔离的无用户存档的视觉样板展示实际组件；不操作用户现有接单、购买或写入其存档。

测试对实际生产组件覆盖按压开始/取消/释放、拖动取消、多指、禁用/销毁/异步回调等行为；纯配色/排布用截图核对，不写仅匹配源码字符串的装饰性断言。运行相关检查、完整回归、类型检查与Cocos构建。构建通过、静态渲染通过和用户实际体验验收分开记录。

本修订覆盖2026-10-29卡通界面设计中蓝色底栏、宿主与图片叠层、文字关闭及任何与本次明确要求冲突的呈现；原圆润立体卡通方向、地图数据、玩法经济和保存规则保留。
