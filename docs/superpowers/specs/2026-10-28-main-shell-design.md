# 主界面导航与交付弹窗

用户标注图及随后说明是本轮已确认的界面要求。沿用黄色地图，不修改订单手机页，等待用户研究参考结构。

- 顶部为圆形头像占位、昵称（暂用“澄川骑手”）、玩家等级与经验、余额、评价。正式图标由用户制作后提供路径，当前仅用代码占位图形，不生成新美术。
- 底部五入口：招募、车辆、抢单、站点、地图。抢单突出；招募和站点尚未上线，灰色占位、无点击事件；地图表示当前页面。配送中车辆和抢单置灰禁用，避免中途操作。已具备功能但未满足解锁/购买条件同样禁用，文案说明原因。
- 被动收益尚未开放，整个信息项不渲染，不展示0或虚构收益。未来有真实解锁状态与收益账目后再加入。
- 用户文案约束：底部入口只有图标与名称，不附加“未开放”“配送中”“当前”等说明；不可用仅用置灰和禁用表达，不擅自添加状态或引导文字。
- 用户纠正：“地图”是地图解锁系统入口，当前主页面是配送主页。点击可查看县城/城市/省会/一线/国际一线与原定解锁条件；当前仅县城可用，其他地图灰色禁用，不伪造后续阶段经营或地图切换。配送中可查看，到达需求或结算弹窗优先，窗口重建保留地图页。
- 用户最新外观要求：底栏无背景，待命地图延伸到底部，地图版权与比例尺仍位于导航上方；抢单按钮仅黄色背景与大号“抢单”两字，不显示占位图标。
- 导航在配送时保留，活动面板上移118设计像素，地图同步缩短，定位按钮保持在地图右下角。
- 到店等候2秒保留，主状态明确显示“正在取餐中”及剩余秒数。
- 当前县城的“放门口”需求到达后自动弹窗选择，不在底部摆交付选项。遮罩60%黑色；未选择前不能点击遮罩或关闭跳过。刷新、切后台、窗口重建后从arrived状态重新展示，不提前结算、不重复奖励。普通单继续自动结算。未来带垃圾/上楼等需求复用该交互，不提前生成未实现需求。
- 暂不做特殊订单触发、骑手/站点经营、昵称编辑或新的经济字段。存档只增加下述可选餐损提示标记。

## 追加：配送中餐损事件

用户明确要求本轮先补餐损，不实现雨天或修车事件。仅原本已抽中餐损的订单，在取餐完成后、送餐路段约一半处显示“路程颠簸，餐品损坏了”，2秒自动消失，不阻断配送、不要求确认。触发基于所选真实路线的距离进度，不新增随机抽取。原结算损坏、评价与收入保持一致，不额外罚款。

给活动订单增加可选布尔字段damageNoticeShown，领取显示机会后持久化，旧档缺失按未显示处理；每单最多一次，刷新不重复。提示独立于保存错误和结算弹窗，正常订单无该提示。遇到大帧直接送达则不在结算后倒放事件。UI重建保留尚余的2秒展示，后台计时冻结。

后续打磨已记录：点击、取餐、送达、结算、升级的音效与动效，配合用户提供的正式图标统一接入。当前没有完整音效与动效，不将其计为完成。

验证沿用协作边界：助手检查实际代码逻辑、数值、存档兼容并构建，用户验收页面，不使用浏览器自动操作。
