# 《鼠影狙击》首版设计

状态：设计草案，等待用户确认后进入实现计划。

## 目标与参考

制作手机浏览器点击即可玩的竖屏 3D 搜寻射击游戏。参考用户指定的《狙击外星人》的搜寻、开镜和射击循环，以用户描述的静止伪装老鼠为本作目标。场景、模型、界面和音效使用自制资源。

目标玩家是使用手机、希望在碎片时间完成一局观察挑战的休闲玩家。第一版验证：普通视野难以发现目标，开镜后可以凭细节找到目标，射击反馈清楚，完整一局可以重来。

## 技术与交付形态

推荐 Cocos Creator 3.8.8 + TypeScript，建立独立的 `rat-sniper/` 项目，导出 Web Mobile 网页构建。保留现有 `cocos-dodge-demo/`，避免混入之前的躲避玩法。

与之相比，2.5D 全景图片加可点击目标制作较快，但不能自然呈现老鼠的体积、各部位和场景遮挡。本作选择真实 3D，以匹配用户描述。

最终首版产物是 Cocos 项目、Web Mobile 构建和手机预览方式。能导出网页不代表已经符合 TapTap 某一发行通道的要求；平台接入阶段单独核对。

## 首版关卡

只有一个低多边形卡通庭院场景，包含白墙、蓝色窗框、黑色栏杆，以及管线、空调和花盆等少量环境细节。

玩家位于庭院内的固定观察点，位置不可移动。周围布置可观察的建筑立面和角落；左右视角可连续旋转 360°，上下俯仰限制在约 -55° 至 +60°，防止翻转。

首版固定放置 6 只老鼠，限时 90 秒。位置和颜色由关卡配置确定，重新挑战保持相同布置。所有目标都必须能够从固定观察点转动视角找到并击中，不能完全藏在实体后面。

老鼠搜索期间保持静止。白墙上的老鼠为白色，蓝窗边为蓝色，黑栏杆上为黑色。通过同色材质融入背景，玩家仍可凭耳朵、尾巴、轮廓和体积辨认。造型由可辨认的头、耳、身体、脚和尾巴组成。

## 手机竖屏操作

- 在场景区域拖动，改变相机朝向；拖动不会开枪。
- 左下方按钮切换普通视野与瞄准镜，切换前后保持瞄准方向。
- 右下方按钮朝画面中心准星开枪，可在普通视野或开镜状态射击。
- 支持一根手指拖动、另一根手指点击射击；不同触点独立处理。
- 无限子弹，无换弹，射击间隔 0.55 秒，避免长按无间隔扫射。
- 界面适配手机长屏和安全区域。横屏时提示竖屏游玩，不依赖浏览器强制锁屏。

普通模式显示当前朝向的广角画面；360° 场景通过转头逐段观察，不能在一个平面画面里同时显示所有方向。

开镜采用固定约 4 倍光学放大：同一相机缩小视场角，屏幕中央覆盖圆形瞄准镜，镜外遮黑，保留操作按钮。放大后可见范围缩小，并降低转动灵敏度，便于精细瞄准。

## 射击与部位反馈

推荐首版所有有效部位命中均可一枪消灭，突出搜寻而不是反复补枪。部位区别先体现在反馈和得分：

| 命中部位 | 反馈 | 得分 |
| --- | --- | --- |
| 头部（含耳朵） | 金色准星反馈、“精准命中”、清脆提示音 | 150 |
| 躯干 | 白色命中标记、“命中”、短促击退 | 100 |
| 四肢或尾巴 | 小幅侧翻、“擦边命中”、不同提示音 | 50 |

命中后播放短暂卡通反应并移除目标，已消灭数量只增加一次。搜索阶段不显示目标轮廓或血条，命中后才给确认反馈。首版不使用血腥表现。

射击判断沿准星射线寻找最近的有效交点，先命中墙体就不能击中墙后目标。部位判定与可见模型贴合，细尾巴不会使用覆盖周围大面积的命中框。打空或打中环境有轻量反馈，不增加完成数量。

## 一局流程与界面

开始界面显示庭院、简短操作提示和开始按钮，点击后计时。

游戏中顶部显示剩余时间与已消灭数量，中间是准星，下方为开镜和射击按钮。普通模式下方有简化枪身示意；开镜后以瞄准镜为主。

在倒计时结束前消灭 6 只老鼠立即胜利；时间归零仍有剩余目标则失败并停止射击。在同一次更新中，先结算已经接受的射击，再判断超时；超时后不再接受新的射击。

结算显示胜负、消灭数量、得分和用时，提供重新挑战。重来恢复目标、时间、相机初始朝向和普通视野，清除上局反馈。

切到后台时暂停计时，回到页面后点击继续恢复。音频在用户首次交互后启用，并提供静音开关；声音不可用时仍可凭画面游玩。

## 模块边界

- `LevelDefinition`：场景元素、固定目标位置、颜色、时间和数量配置。
- `RoundSession`：开始、计时、暂停、得分、目标存活和胜负的唯一状态来源。
- `LookController`：触点归属、相机转向、俯仰限位和开镜视场角。
- `WorldBuilder`：庭院模型、老鼠模型和对应射线命中几何。
- `ShotResolver`：最近交点、实体遮挡和目标部位识别。
- `HUD`：竖屏按钮、圆形镜罩、进度、结算及命中反馈，向游戏控制层发送操作意图。
- `GameController`：连接上述模块，统一处理开局、射击、结束与重来。

场景配置和游戏规则不依赖 TapTap。等平台通道确认后，在外围增加平台适配层，避免把平台 API 写入射击与胜负逻辑。

## 首版验证边界

执行必要的脚本类型检查和 Web Mobile 构建，确认可交付产物。用户先前要求不检查游戏，因此自动试玩、截图检查和游戏审查需在用户重新授权后进行；不能把构建成功表述为手机实际体验已验证。

交付后由用户重点体验：竖屏触屏是否顺手、开镜后的搜寻难度、三种部位反馈、成功与超时后能否重来。6 只与 90 秒是首版参数，可根据用户试玩调整。

## 后续 TapTap 接入顺序

遵循 TapTap agents.md 的分阶段流程：先交付完整的本地可玩循环，再确认当前平台接受的发行形态、模板和包结构，然后处理上传与平台适配。按实际需要逐项增加排行榜等能力，不预先加入账号、后端、支付、广告、联网或多关卡系统。
