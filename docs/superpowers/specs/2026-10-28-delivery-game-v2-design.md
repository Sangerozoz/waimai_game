# 《送外卖》V2整体设计与数值约束

2026-10-28。本稿整合当前县城版、点击加速、到点取送、多单规划、体力补给及后续经营。配套[七阶段实施方案](../plans/2026-10-28-delivery-game-v2.md)。

**状态：新版设计草案，尚未实施。** 用户明确了玩法方向；本文推荐的时钟解释、操作规则和首轮试算参数不是已经验证或已获体验接受的成品规则。当前构建仍按现行规则运行，已通过的历史验收不作废。新版开发以逐阶段验证为准，不能宣称方案审计能保证实现没有bug。

## 1. 产品与完整循环

二维真实路网、虚构地名、竖屏黄色配送经营游戏。玩家自己挑单、规划、取送和补给；车辆沿道路自动移动，玩家可以连续点击加快当前行程的进程。随后经营骑手与站点，解锁城市与收藏。

完整循环：查看大厅 → 接1–3单 → 预览路线/时限/载重/体力/补给 → 安排停靠顺序 → 出发自动行驶并可点击加速 → 到点取餐/交付/补给 → 逐单结算并继续余单 → 全部完成后继续接单与成长。

| 已明确的方向 | 本稿推荐规则或待验证内容 |
| --- | --- |
| 自动播放去商家和去顾客的行驶动画 | 首版不做摇杆驾驶、现实GPS移动 |
| 拉长基础表现，点击越密集进程越快，不点也能走完 | 点击先作为行程快进；是否真的改变游戏内车速仍属产品取舍 |
| 基础约10秒，密集点击约3秒为用户举例 | 用20游戏分钟路段试验10秒→约3秒，不给每条路固定时长 |
| 完善取送操作、多单策略、后续补给 | 推荐到店点取餐、到顾客点送达；最多3单，先出发前组单；单条体力值 |
| 继续经营、站点、城市与终局路线 | 将实施重排为M1–M7，核心配送增强在经营扩张前验证 |

## 3. 统一状态与操作规则

### 3.1 三种对象

- **订单Job**：唯一ID、商家/顾客、餐品/重量/费用/需求、承诺期限、accepted/carried/settled状态、固定规则参数、损坏结果、交付结果和唯一回执。
- **行程Trip**：骑手位置与当前道路进度、持有的1–3单、路线与停靠任务、当前游戏时间、出发参数、已执行事件序号。
- **地点动作StopAction**：pickup/drop/supply/rest；关联订单、地点、服务游戏时长、表现时长、已消耗进度和一次性支付/恢复标记。

行程基本状态为 planning → moving → atStop → servicing/waitingChoice → moving/finished；途中原地休息另允许moving → servicing(rest) → moving。已出发订单状态单向 accepted → carried → settled；出发前撤回只是释放保留槽位，不重新生成订单。旧活动由兼容路径运行，不强行套新状态。

原地休息是独立rest动作，保存暂停前的edgeId、方向、edgeOffset及剩余停靠任务；休息后恢复该路段进度，不能假装到店或从道路起点重走。旧活动完成前不开放NPC收益与新资产经济变更，防止旧单单钱包校验被并行被动入账破坏。

### 3.2 必须成立的规则

1. 候选单、持有单、已结算单互斥，同一订单不能重复接取或再次发奖；持有总数不超过3，M2限1。
2. 每单先取后送；每次取餐之后的真实携带重量不超过车辆载重。不能只检查每张单的重量，也不能简单把所有已接重量视为同时携带。
3. 一个计划必须覆盖每张未完成单所需的取送动作；不含重复交付、孤立取餐、无效ID或不可达路段。零距离相邻动作也要消费任务，不能除零或卡在原地循环。
4. 首版只在出发前接单。出发前可撤回未执行的接单，不扣钱、不移动车辆；出发后不提供普通撤单。停靠点可重排剩余合法任务；行驶中查看计划不瞬移或重置当前路段。
5. 重排必须整体校验成功后替换；失败保留原计划、资源和时限。超时预警不等于物理非法，玩家可以自愿选择会超时的合法组合。
6. 已接单超时仍可送完，评价按单扣一次，没有额外罚款、强制失败或餐品消失。所有订单完成后才进入无活动行程状态。
7. 固定动作最终要完成或有明确重试；弹窗、存档重试、后台恢复不能重复取餐、交付、付费或恢复体力。

追加订单的接取也要先生成至少一条资源/道路/载重合法计划才提交；没有合法计划就保留原持有单，不能接完才告知无路。单独候选≤10km不代表任意三单重排≤30km，整计划必须重新测算，不能用3×22点当通用体力上界。

同店连续取餐且容量允许时合并一次服务；容量不够则可取一单、送一单、返回取另一单，每次实际返回产生真实路程和服务时间。订单交付后立即入账，回执不强迫整趟结束或返回大厅。

最后一单首次交付后结束行程，取消尚未执行的可选补给并释放对应预留，不扣未执行费用；已经执行的路程、服务和支出不回退。需要继续补给/休息可在无活动状态操作。

## 4. 时间与点击加速

### 4.1 三种时间分开

| 时间 | 用途 | 加速/暂停规则 |
| --- | --- | --- |
| 现实前台时间 | 账单在线时长、后续经营 | 保持真实经过时间，后台不计；不受点击和游戏内等待快进影响 |
| 玩家行程游戏时间 | 取送预计、各单期限、补给耗时、以后保温 | 行驶时与位移同步快进，同一行程所有未完成单共享；服务按动作定义推进 |
| 现实表现时间 | 车辆动画、取餐和补给反馈 | 行驶可点击快进；服务动作单独配置，不按行驶压缩比硬换算 |

阅读、出发前规划、到点选择与结算查看暂停该行程的配送钟，不消耗体力；实际行驶和执行服务动作才付出明确游戏时间。后台冻结配送、动作和加速，前台恢复后不补算隐藏区间。音效/界面动效不决定业务计时。

### 4.2 首轮加速候选参数

- 行驶基础换算R=120游戏秒/现实秒；道路游戏时间=实际道路米数×3.6/车辆km/h。
- 加速倍率B在1至10/3之间。每次有效点击增加0.5倍率，按现实秒线性衰减1.5，最多按8次/秒的有效输入累加；超额输入不继续提高倍率。
- 每帧对实际倍率积分，同时推进该段位移和行程游戏时间，不能只改车辆坐标、只改动画或漏算其他单倒计时。不同帧率使用同一算法。
- 20游戏分钟行驶基准为10现实秒，理论持续满倍率为3秒；实际从基础升速会略长，须M2体验调参。车辆更快仍减少基础游戏与表现时长。
- 候选参数精确积分下，首击在0时刻且均匀8次/秒约3.33秒、6次/秒约3.51秒、4次/秒约4.32秒；固定2秒取餐另算。上述仅道路段数学值，M2以实际实现误差和手感验收，不宣称整个订单3秒完成。
- 到站即停，跨过的路段事件按顺序处理，剩余帧时间不得越过需要玩家确认的停靠点。零距离段直接进入地点动作，不播放假路程。
- 停靠/后台时加速清零，服务中点击不累积下段加速；读档恢复基础倍率，实际进度、时限和资源不回退。
- 点击首版不额外耗体力、不多抽餐损；不操作仍可正常成长。若产品决定点击要挽救超时，必须另建真实提速规则并重新审计，不能复用本节“时限结果不变”的验收。

加速只影响玩家行程；不快进自然日期、刷新额度、NPC骑手收益、离线收益或在线时长。不点/慢点/密集点走同一计划，游戏到站时间、每单收入、体力、路程和事件结果应一致，区别是现实等待。

### 4.3 时限

出发前规划不计时。出发时为每单固定 dueAt=出发游戏时刻+独立最快取送道路用时+必要服务用时+类型余量。独立最快由同一出发点计算，不以玩家选择的绕路计划延长承诺。

普通余量300秒；加急首轮候选120秒。取餐服务候选60游戏秒/2现实秒；同店合并一次。交付确认本身0游戏秒，后续上楼等动作在对应阶段定义明确服务用时。不能提前把未实现的需求计费。

重排、改路线、查看账单、刷新页面不重建dueAt。单单预估与实际用同一时间函数；ETA必须包含剩余所有停靠及补给耗时。允许浮点显示取整，但业务用固定精度、不得因分钟文案取整误判晚到。

## 5. 多单与候选

大厅基础池为10个有稳定ID的订单槽位，持有单另列。出发前接取只将槽位标为保留，不立即生成替代订单、不推进生成游标；可接区为10减持有数，保留区的订单不能再次接取。撤回恢复原ID/原槽位/原结果，开关手机、预览、接取/撤回循环不能免费换单。已接至少一单时不允许手动刷新。

仅订单首次成功交付或合法手动刷新消耗相应生成游标并补候选；逐单交付释放的槽位按骑手当前位置和可达道路补齐，余单的槽位仍保留。候选可在后台补好，但活动行程中不开新接单。无活动时恢复10条完整可接列表；手动刷新与正常交付补单的额度分别记，不混淆。当前县城容量保底沿用，后续城市至少保留可独立完成的正常订单；不能要求玩家先接满3单才能出发。

M3最多3单、最多6个必要任务。真实有向道路上枚举满足先取后送的顺序，检查载重并计算各单ETA；同店任务合并时不得隐藏容量问题。建议路线不超过3条，按总路程/时限风险等展示必要信息，不铺满地图文案。

加入一单时展示新增绕行、各单预计送达/超时、载重；M4再加入体力/补给。物理上可执行但会迟到的组合可接，不能把用户的每一种选择都保底变成准时。单单推荐必须仍有可准时方案。

## 6. 体力、补给与防卡死

M4前体力机制完全关闭，不显示假体力。启用后先只管理玩家一条体力，不给每个NPC增加逐个吃喝的负担。

| 参数 | 首轮试算值 | 含义 |
| --- | --- | --- |
| 最大体力 | 100点，内部10000整数单位 | 旧档启用时给满，不追溯历史消耗 |
| 行驶消耗 | 2点/km | 实际路程只算一次，与持有单数、点击次数和动画秒数无关 |
| 取餐消耗 | 每次实际取餐服务1点 | 同店合并取餐一次扣一次 |
| 交付消耗 | 每单1点 | 交付动作消费一次 |
| 水 | ¥2，恢复20点 | 60游戏秒/2现实秒 |
| 饭 | ¥5，恢复60点 | 300游戏秒/5现实秒 |
| 无活动单免费休息 | 20现实秒恢复至100 | 无配送时限推进，无金币/广告要求 |
| 活动中停靠休息 | 10现实秒恢复20点 | 付出600游戏秒，所有未完订单计时；免费、可重复至足够或满 |
| 出发预估余量 | 结束至少留1点 | 覆盖边界精度，仍需逐段与服务校验 |

这些是候选参数，不是用户最终确认或游戏实测平衡。县城最长普通单10km，取送消耗至多22点；示例4km单为10点，同店8km三单为20点。实际生成和停靠分组是审计前提。

### 6.1 出发与重排检查

- 模拟整个计划：每条路段、取餐后载重、动作消耗、恢复上限、可到达的补给地点、补给费用均须可执行。不能只有最终总体力为正，却在到达补给点之前已经耗尽。
- 计划内付费补给费用从可花余额中预留，尚未消费时不从钱包重复扣款；所有后续购买均尊重预留。删除或修改补给只在新计划验证后释放/调整预留。
- 需要先有的钱不能依赖还未完成订单的预计收入。余额不足时允许先休息再出发或选择无付费补给的短单。
- 满体力/恢复为0时付费补给禁用；恢复封顶，不能购买后超出上限、出售体力或赚取差价。补给不增加订单数、经验或线索。
- 同一地点休息/补给只能主动执行，不自动循环。计划不能包含无恢复、零进度的无限服务任务。

### 6.2 必须保留的恢复途径

零钱、零体力仍可免费休息，恢复后接正常单。活动中体力意外不足时，允许在当前道路进度处原地安全停车休息，不需要再消耗体力移动到商店；恢复后从同一位置继续，不瞬移、不抹去耗时。所有单即使超时仍可完成，不清空货物，不因没钱强制失败。到点零体力仍可打开操作/休息，不锁住整个界面。

首轮低体力不额外叠加随机事故、扣钱或连锁减速。低于行驶/服务所需时先选择恢复；靠预估与可恢复停靠解决，不在路中突然弹出付费墙。不可达等程序异常走明确恢复/备份流程，不以清档作为唯一出口。

### 6.3 正收益底线

县城最低基础¥15、最低评价20、最重餐损保留50%，不叠加损坏折扣；最低档与等级/站点倍率至少1。最低单收入=round(1500×(0.85+20×0.003)×0.5)=683分。

最长单22点体力，从0补足并留1点可喝两次水，花¥4，仍净赚至少¥2.83；吃一份饭花¥5，仍净赚至少¥1.83。免费恢复下必要现金成本为0。该边界不代表正常收入、运气概率或实际体验，只证明候选县城费用没有强制负收益陷阱。

上述付费算例只证明价格与收入边界；是否能先到补给点另由逐段检查和原地免费恢复保证，不能把体力总量充足等同于路线可执行。

后续城市重量、需求、天气、保温和服务消耗改变时，必须重新验证最低可持续单，不将县城证明照搬至国际挑战。必须保留普通可持续单，不能让所有订单变为高风险组合。

## 7. 餐损、收入、经验与账单

### 7.1 逐单结算

每单基础费与规则、行程出发时的车辆/经验收入倍率冻结；钱包、当前总评价、累计经验和完成单数不冻结。每次交付以当前评价叠加本单影响后计算钱，再给10经验、计1单。单内评价变化限−10至+6，总评价20至100。

行程同时冻结站点收入倍率、车辆强化及已显示基础费中的天气补贴；评分变化不回写旧单。首版有活动订单时禁止更换/分配玩家所占车辆、升档/强化、站点升级、切换城市和NPC队伍/配车变更，仍可查看面板；NPC在既有费率下正常计息。禁止条件由业务层执行，不只置灰按钮。

收入以分计算，非负金额四舍五入到分：含一次天气补贴的基础费×车档/强化倍率×出发经验倍率×更新后评价倍率×站点倍率×一次餐损保留。

同趟中经验可以即时升级，但已经出发的余单保留本趟冻结倍率，下一趟使用新等级；这是对“一单一趟时下单即用新等级”的明确扩展，不回写已完成收入。不得用同一份旧玩家钱包快照结算三次覆盖收入。

### 7.2 风险不随帧率膨胀

M2–M4先保留按单冻结的既有餐损概率和结果，一单最多一次损坏折扣。提示只在已经携带餐品的路段出现；加速处理不能跳过或重复提示。

后续M6引入路况应对时，另设计持久化路段事件与每单风险阈值，按真实路程/选择累计，不能每帧、每点击或每途经一段都重新抽整单概率。多次波及取最重程度或封顶累计，禁止对同单重复乘50%把收入打没。未取/已送订单不受损。

### 7.3 账单

配送费、经验、单数和评价按订单唯一交付登记；实际里程按行驶增量一次登记，跨单共享不重复。在线为现实前台时间；现实本地午夜分日，不使用加速后的游戏钟切日期。跨午夜行驶增量按真实前台时间轴先切段再记账，允许某日完成0单但已有行驶里程。补给支出单独记，配送费不因买饭减少，净收益=配送费−补给等实际经营支出。

历史账单维持原口径，新记录标注内部统计规则版本；缺历史仍显示已知下限，不捏造费用。行为重试、回执重开和刷新不重复登记。

### 8.1 NPC收益与线索

NPC不增加玩家经验、玩家城市解锁单数或特殊大单次数。正常在线被动累计P≤当日玩家实际主动配送费A×7/3，A不含初始钱、NPC、广告、退款；补给不重复扣减A。未跑当天第一单的半速段独立记账。离线/零主动半速最多8小时、单次上限当前城市平均单笔收入×500；按真实时间区间一次领取，跨午夜分段，时钟倒退不生成收益。

**完整NPC基础公式：** 每名在岗骑手每现实小时毛应计=最高已解锁城市平均基础费×骑手档位收入倍率×骑手强化收入倍率×实际配车档位收入倍率×车强化收入倍率×站点倍率×评价倍率×6。骑手档位倍率为1/1.12/1.25/1.40/1.57/1.76/1.97/2.48/2.65/2.78，与车档收入倍率同表，不能用档位编号1–10相乘；不含玩家经验倍率。城市平均基础费由配置产生，当前基准为¥20/30/47.5/72.5/112.5，不用历史样本均值。实际收入受正常在线上限或半速/离线上限约束。

计息先按旧状态结清到业务边界，再应用新状态：招募/上岗/闲置、配车、车/骑手升档强化、玩家评分、站点、最高解锁城市、首个主动交付与午夜均为分段边界。新增/升级资产不能追溯影响之前等待区间；收益计算保留分的小数余量，不能每帧四舍五入制造额外钱。

正常在线封顶后停发，被截部分舍弃；处理游标仍前进，A后来增长也不补发此前等待收益。首单完成先结清之前半速区间，再增加A和进入正常在线，午夜后也重新按各来源分类，不把同一时间段当半速和离线领两遍。

每次离线/零主动半速领取先确定一个不重叠的来源区间，按真实时间整体截取最近最多8小时，再按午夜/费率边界切分；8小时不能对每个日段各应用一次。500单金额上限对该次完整领取总和只应用一次，不按骑手、日期、费率段分别重置。超时长/超金额部分舍弃，已处理游标推进到原区间末端，不能通过重开再次领被截部分。

领取上限的平均玩家单笔收入另定义为：最高已解锁城市平均基础费×玩家实际配车档位/强化收入倍率×经验倍率×评价倍率×站点倍率；不含随机餐损、补给支出、历史均值。对离线窗口在离线开始时冻结该参考值，对半速窗口在窗口建立时冻结；改变资产先结清旧费率区间，不重置同一未领取窗口的8小时/500单上限，不自动抬高旧窗口的参考值。费率分段不是新的领取机会。

线索在一线且玩家车/在岗骑手至少A后，每单车辆/骑手各独立5%，各类每3条依次开放S/SS/SSS资格；站点5与国际后兑现。国际入口不要求隐藏车或隐藏骑手，不能与隐藏解锁形成环。隐藏车特殊大单约10%，保留普通单。隐藏资格按车辆/骑手类别及档位永久保留，供同档副本复用；收藏按已解锁型号记录，车与骑手类别不串用。具体资产的购买、分配、升档和强化状态按实例独立。

线索只在玩家订单首次成功交付时与唯一回执一起发放，资格条件按该行程出发时冻结；预览、接取、撤回、刷新、休息、NPC计息和重复回执均不抽线索。M6开放一线时就实现资格判断、独立确定性抽取、累计和保存，M7只增加兑现。每类别累计到3/6/9条依次开资格，未买S也可继续积累SS/SSS，9条后不再产生无用计数。

按既定“先攒后兑现”，若800单起始终满足条件，到2000单前有1200次机会，各类通常早已攒齐9条。这不是卡点，意味着后期主要追求是购置、收藏与强化，不把线索宣传为国际阶段的长期随机目标；如要改变这一定位，另立变更，不能临时调低5%或清除已攒线索。

SSS强化每实例1–30级，收入每级+1%、车速每级+0.5%，30级分别1.29与1.145，车与骑手状态不串用。强化费用从旧“玩家当前平均单笔收入”改为独立候选报价基准：最高已解锁城市平均基础费×固定SSS档收入倍率2.78×当前玩家经验倍率×固定参考评价80的倍率1.09×当前站点倍率；不含玩家临时装备、实际评价、所选低级地图或目标实例现有强化倍率。

固定基准先四舍五入到整数分，当前强化等级L升到L+1的报价=基准分×L，提交前固定规则profile与基准并检查余额，不因确认弹窗中切装备等动作变动。固定同一基准时1→30总费用为基准×435；若未来重新引入当前强化倍率，则是×516.2而非×435，必须改审计与价格展示。此为修复价格锚点套利的V2候选规则，M7仍须验证实际回本与追求时长，不追补旧已付费用。后期温度流失、概率和成本在M6/M7重新校准，不直接套旧秒率。

每日免费刷新2次、未来广告额外最多3次；广告不成功不消耗额度，不做假回调。未接入时10条普通可接；SDK接入后才评估1特殊广告单+9普通。免费恢复与正常接单不依赖广告。

## 9. 架构、存档与数值安全

保留OrderBook作为统一操作入口，内部新增行程、计划、骑手资源与业务变更处理；UI只发送操作、读取状态，不自行扣钱/体力或推进某张单的独立钟。RoadRouter继续负责真实路段，预计与执行共用计算。

新存档采用独立schemaVersion=4及规则/参数profile标识，不能把多单字段硬塞进只理解一单的v3校验器。旧v1/v2/v3先严格验证；活动单继续旧时钟、结果与进度直到完成，再开放V2，不强迫旧单突然消耗体力或改成手动交付。钱、车辆、经验、地址、回执、次数和账单保留。

业务操作必须是完整状态变更：唯一命令/动作标识、单向订单状态、单调revision/event序号共同防重；钱、体力、动作、回执和账单写入同一个完整快照。保存失败重试同一已确定结果，不重新扣款/抽奖；保留待提交操作并显示已有错误反馈，不假装持久化成功。

有待提交操作时，冻结后续经济命令和跨移动边界操作，允许查看与重试。随机结果由已经持久化的会话种子、订单ID、事件序号与规则版本确定；不能只缓存内存结果，因为保存失败后重启会丢失缓存。取餐完成、交付结算、补给支付/恢复、购买、换城等边界提交成功后才继续。随机种子须先持久化再开放相关操作。

同源多标签必须有可靠的单写者互斥或事务提交机制，并在提交时复核revision；无法取得写权限的页面只读并允许回到已有运行页。localStorage“读取比较再写入”不是跨标签原子CAS，不能单凭这一点宣称并发安全。M2先验证目标宿主的互斥/事务能力，无法可靠提供时不开放多写者经济操作。

V4校验必须逐项重建：不再要求当前玩家钱包等于每个订单的出发快照；允许活动中补给扣钱、前一单已经结算、另两单继续；账单允许0单有里程，补给支出也可发生在0单日。玩家经验=玩家完成单数×10仍保留，但NPC单数独立，不能混进玩家解锁计数。旧校验器只用于旧档/旧活动兼容，不直接校验新状态。

保存动作进行中的已耗时、已支付与已恢复状态；重载只完成剩余服务。保留有效备份与迁移前快照，旧标签写冲突不得覆盖新版；未知未来版本不得被当作损坏自动用旧档覆盖。损坏/无法读取需提供明确恢复路径，不要求清档才能继续。

内部钱用整数分、体力用整数单位，累计路程与游戏时间使用固定精度或显式残差；先校验安全整数/有限值再提交。余额与资源不能负数、恢复不能超上限；超出范围拒绝操作并保留原状态。禁止用UI取整后的分钟参与超时判断。
