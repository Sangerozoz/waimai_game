## 这次怎样改变旧派生布局

- 原16栋同类小补景不冻结保留，改为110栋大小不同的连续商住。38×24m大模块23栋，加34×20m、30×22m、28×18m、24×16m、22×14m中型楼体；18×12m至9×7m只填不规则余地。中大型模块占新增足迹约82%，并非靠许多零散小房子虚增对象数。
- 新增楼层3层37栋、4层37栋、5层18栋、6层18栋，3–4层占多数。包含连续店屋84栋、转角商住16栋、紧凑内院公寓10栋；地面锚点和临街方向独立记录。
- 原大校园/运动场、大公园、广铺地布局不再沿用。仅在放楼后仍合适的安全空隙安排8×8m级微型口袋绿地和3×1.5m小花槽，树从旧派生96株减到18株，不在屋顶种树。
- 原脚本叠加较大的退让已收窄：实际道路每侧留2.5m人行道；原楼外保护1.5m；新楼放置掩膜每侧1m，邻楼约留2m必要通道，另有0.5m栅格保守量；样板边界保护1m。街边楼体实际还受新楼保护掩膜影响，约在合理3.5m级退距，不更改原路宽。
- 原线状水道无测绘宽度字段，继续按20m保守水体宽度，再留1m岸边保护；入口半径5m保留。新楼不能为了覆盖率穿路、盖水、压旧楼或挡入口。

使用最大至最小10轮模块后达到52.564%，没有为冲60%继续塞更小碎楼。当前几何、1m新楼保护及原地块形状限制进一步规则模块放置；算法不是全局最优排布证明。当前剩余地面依然需要人行道和通道，不能把它们都当可继续占用的空地。

## 固定开发接入

入口仍为`bounds/parcels/addedBuildings/sceneFeatures/trees/sourceBuildings/sourceRoads/sourceWaterPolygons/sourceWaterways/entrances/constraints`，单位均为地面米。原样板的`sourceBuildings/sourceRoads/sourceWaterPolygons/sourceWaterways/entrances`五数组逐值复用，包含134处原建筑足迹、59条路的ID/方向/节点/浮点points、3条原水道和两原入口。这里没有新增经营POI、节点、路由或订单地址。

| 字段 | 接法 |
| --- | --- |
| `addedBuildings[].id/parcelId` | 新ID`DV2-B*`；`parcelId`指向`DV2-BLOCK-*`建筑组引用，稳定于当前冻结来源和脚本 |
| `addedBuildings[].footprint/groundAnchor/heightMetres/floorCount` | 新足迹顶点保留4位小数；高度9/12/15/18m；不反推/改动原几何 |
| `addedBuildings[].module/styleProfile` | 店屋/转角/公寓；暖白浅米立面、浅屋顶、适量橙色店招、受控玻璃反射与平屋顶禁树提示。实际画风按概念参考重建，平面图棕色只用于新旧区分 |
| `addedBuildings[].streetFacingHint` | 临近原路ID/最近道路点/朝街法向/原路宽；只指导立面，不新增路线 |
| `parcels[].renderGround` | **29条`built-block`记录为建筑组引用，`renderGround:false`必须跳过填地**，且不重复计面积。其余125条是真实残余地面 |
| `parcels[].rings` | 多环/内孔按evenodd填充；旧楼、新楼、水和路的洞不能被地面涂满 |
| `sceneFeatures[].bounds` | 继续使用左上/右下地面点；40处小花槽。实际绿地面积已经体现在地面分区，不重复求和 |
| `trees[].groundAnchor` | 18株地面树，每株冠幅5.5m；地面对应微型绿块，不套旧96树列表 |

新地面分区边界近似0.5m，仅用于装饰；原city浮点坐标没有降精度。树/花槽`parcelId`指向真实地面分区。若旧读取器只懂样板旧`landUse`名，优先使用`groundColor/groundMaterial`与`renderGround`，不要按旧名称自动恢复草坪。两原入口为榕树街食堂1623821046、晴川广场9657208284，保持原坐标与身份。
