# 整区底图城市地图渐进建设计划

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task; reuse the eligible Hermes/OpenAI API map role and preserve disjoint ownership.

**Goal:** 逐区建立可在同一Tiled项目检查、可跨区导航的城市地图，不再把固定朝向单栋PNG硬贴任意旧路。

**Architecture:** 分区整图负责建筑与可见道路的一体化画面；独立矢量路线层导出全局路网。所有区域共享像素坐标契约、图块偏移和跨界接头；正式运行按视口加载区域图片。旧地图/源路网/存档保持，不把它们的几何强塞到新图，也不在此阶段直接切换正式游戏。

**Tech Stack:** 已验证的Hermes→OpenAI API Images、PNG原生母版、Tiled TMJ图像/对象层、Python数据导出、现有导航小样；正式Cocos显示与产品接入另按范围集成。

**Status:** 用户认可总体布局方向，并最新要求地图总区域面积约为原25图地图的1/4。功能与疏密意图保留，原9图生产格预案停用；改为优先4～6张、暂以6张为预算上限，具体分块由相邻两区实测后冻结。导航小样已获认可，整城美术/正式游戏尚未验收，不批量生图。

## 最新规模约束（覆盖旧9图/16图预案）

- 默认按**总面积约1/4**理解；同形状情况下长宽各约原先一半，不是长宽都缩至1/4，更不是把图片像素直接缩小。
- 缩减街区、重复设施与道路总量；保留核心商业、住宅、公建、小工坊、郊区和自然过渡，不把原整城内容等比例挤进小图。
- 建筑、路宽和局部细节按小样可读尺度控制。缩面积主要用于减少图片数量和品控成本，不自动等于更高清。
- 图片预算优先4～6张，暂以6张为上限；先做两张相邻图验证真实清晰度与接头，不为凑满格子扩大城市。
- 若细节不足，先减少内容覆盖或验证更高原生输出，不自动回到9/16/25图，也不收紧镜头后冒称达标。必要重大取舍再向用户说明。
- 原C01～C09是已讨论的功能分布意图，可合并进更少生产图块，不再一一等同最终图片数量。旧草图保留历史，当前范围入口为 `../2026-11-06-city-image-map/planning/current-scope.json`。

## 阶段1：压紧总体布局和图数预算，不先批量生图

**目标：** 一张用户能直接看的低成本总体草图，决定区域身份、密度和主干道关系。

**当前约束：** 总区域面积约为旧25图地图的1/4，功能区域合并，优先4～6张、暂以6张为上限。不是将旧范围的建筑全部缩小塞入，也不靠复制现有小样填格子；图数服从真实原生细节、目标近景和范围预算。

- 沿用红展示边界、蓝经营/完整配送边界、绿繁华核心的分区意图；新图中的实际边界另作可编辑层，不改旧selection文件冒充新旧已配准。
- 繁华核心、公建/商业、不同住宅组合、小工坊服务、郊区与自然外围各有身份；住宅约半按整体用地意图，不按张数或楼数伪造达标。
- 总体草图先定主干道、河流/必要普通桥、区域出口和主要地标位置。路是新画面的结构，不是原旧路网的逐点复刻。
- 借用原25拼图的相对体量、楼群组合、前后排和疏密，不重开25图或把名义拼接当精确底图。

**拟建工作目录：** `docs/art/2026-11-06-city-image-map/planning/`。
**交付：** 紧凑范围/功能合并表＋暂定像素密度/出口合同。用户已认可总体功能方向，常规收紧不重复索要同一批准；相邻两区的真实画面与跨区导航仍须交用户看。

## 阶段2：只验证一对相邻区域

**目标：** 不只证明单张好看，还证明两张图可以真实相接并跨区导航。

- 总布局确认后选一个代表性相邻组合；当前小样可作工艺参考，是否成为正式某区由总体布局决定。
- 同一镜头、光照、风格、建筑/路宽比例；风格权威仍为用户原参考与认可25图，不无限递归套新AI图。
- 生图前定共同边界的路口位置/方向/路幅及少量重叠带。尽量沿道路或绿地分区，不切断整栋楼。
- 必要时提供相邻图窄边带作接头依据，不让完整邻图诱发整区构图复制。
- 不让导航线跨越画面里并未连上的断路；修明显接头，不纠缠一两块地砖。

**拟建输出：** `regions/`里的独立原生图/来源记录；`tiled/city-map.tmj`里的两区底图和可编辑路线；`navigation/city-graph.json`里的合并路网。
**放行证据：** 两区实际Tiled关系图、一个能看清的近景、一次真实跨区导航移动。接头/比例/清晰度不通过，不批量扩余下片区，更不擅自增加地图范围和图数。

## 阶段3：把描线/合并工具补到可扩展，而非扩大硬编码

**目标：** 后续每加一区不重新写一套导航。

- 固定每区原生尺寸、有效核心范围、重叠带、全局偏移；保留原始尺寸和源，不横纵拉伸迁就。
- 本地路线转全局像素时只应用一次偏移；底图与路线始终使用同一坐标空间。
- 交点打断、端点吸附、普通路口连通、跨区同名接头合并与重叠路段去重必须显式实现；不同层跨越不自动接通。
- 废弃道路不留孤立导航节点；确有独立车道/不可达区域明确标出，不穿楼补线。
- 取送/停靠点作为独立对象，放真实门口或可达路肩，不把楼中心当道路点、不新增游戏经营事实。

**范围：** 地图数据和工具，只读正式游戏/业务/存档。用户明确阶段完成后再组织游戏阶段测试；跨区工具小样演示不是全套游戏回归。

## 阶段4：沿相邻关系逐区扩城

**目标：** 每新增一区都有实际可看的总图和可运行导航，而非等全套图齐再发现失败。

固定循环：
1. 从总布局取本区身份/主路/接头；制作一张整区候选。
2. 实看建筑与道路的内部关系、尺度、明显破损/断路；不再生成单楼360朝向。
3. 接入同一Tiled主项目，不重建/覆盖用户手调文件；必要新稿另存。
4. 助手负责描中心线和导出，用户不必每条亲画；用户可改节点和指出明显错误。
5. 合并全局图并演示新旧区之间的真实可达路径，维护实际入图数、资源字节和待修项。

区域不同功能和高低密度过渡同时推进；围栏、菜地、院落、小物作为画面内容自然安排，少量独立装饰仍可复用，但不恢复每栋拼装的旧生产瓶颈。

## 阶段5：交可编辑整城包，再做正式接入

**交付：** 一份Tiled城市主项目、分区图片与来源、矢量路网、地标/门口/边界对象、可运行导航预览、未确认清单。原生母版与运行派生分离。

- 运行按当前视口和相邻区域加载，避免把全城合成一张巨纹理；压缩不能改变坐标尺寸或把插值称高清。
- 先核地图数据接口与正式坐标映射，再由对应职责集成；本线不改产品UI、经济、订单规则或重置存档。
- 统计源文件/运行图/解码预算与真实屏幕证据分开。真机性能、正式游戏测试和用户最终验收尚未完成，不提前填写。

## 当前最小下一步

按已认可功能方向将范围压到旧图约1/4、合并功能区并收紧图片预算；随后只用一对相邻区域完成“画面接头＋清晰度＋跨区导航”闭环，再确定最终4～6图分块。此之前不批量生产整城，不承诺仅凭缩范围或图数解决高清。
