# 六页UI结构修订要求

2026-11-02。来源：用户对六页审图意见的修改授权，以及后续对骑手浏览效率的纠正。本轮制作效果图与产品说明，不启动游戏开发、测试、构建或操作存档。

## 1. 不得误解的边界

- **锁住当前颜色基准**：以用户交回的 image 26/27/28/29/31/32 为颜色参考，保持当前浅蓝/白/深蓝字/橙色。不是进一步蓝化，也不是整体去蓝或换色。不得逐稿增加蓝色饱和度、蓝色面积、蓝色罩染、蓝光或蓝色边框厚度。
- **两三屏是完整列表的浏览长度目标**，不是要求一张截图容纳全部数据，也不是把所有卡片等比例缩小。优先调整排布、去重信息、分配主次，保留可读文字和有效点击区域。
- 车辆最新要求覆盖上一轮的双列完整商品卡、删除顶部预览要求：现在为**上方联动预览/详情/购买，下方车型选择宫格**。原单列稿与把十辆车全部详情挤进一屏的稿件均不能继续作为目标。
- 骑手按最多30名NPC加主角31人规划，完整概览约2–3个内容视口；不做每屏3张大人物海报，也不做一屏塞30人。
- 各图是静态交互示意，不能声称已经实现选择联动、购买、滚动或点击反馈。

## 2. 公共规格

以约600×1068的逻辑画幅说明布局，不作为已经精确测量的像素交付。

- 管理页统一约72高顶栏、相同标题字号/基线/左右边距；金币组件共用。骑手/车辆/地图/账单只显示标题与金币；订单大厅增加体力；首页完整HUD保留。
- 共用底栏和橙圆，当前tab只显示一个关闭×；其他tab正常。内容区底部留出橙圆凸起与底部安全区，固定控件不盖住卡片、价格和按钮。
- 金币统一使用金币图标/“金币”，不再把同一种游戏币写成人民币¥。收益加成用“收入加成+X%”。
- 橙色用于消费/招募等动作，蓝色用于查看配置/路线等导航，灰色用于禁止。宫格橙色描边只表示当前预览选中，并附选中标识；不冒充装备状态。
- 不靠细小字号塞信息；常规阅读按375宽设备约12–14及以上逻辑字号、主要交互有效热区由引擎保证。静态图只用于层级与密度评审，不宣称已完成触控验证。
- 样例金币680、体力78/100、评价96、主角Lv.5/累计经验810、阿航Lv.1/今日收入30、小夏未招募/110金币等沿用。主角下级累计经验阈值945来自正式参数。

## 3. 首页

**方向**：保留已认可街区构图，只修正HUD可读性和定位对象。

- 保持现有建筑、路网、光照、地面绿植和颜色；屋顶不新增树木。
- 保持较小头像，金额区域优先分配宽度，数字和加号分离；六位数余额应有排版空间，长金额不能覆盖相邻资源。样例仍为680，不为展示能力改用户样例余额。
- 地址、等级经验、金币、体力、评价、骑手1/2保留；不扩大顶部遮挡。
- 地图增加明确的小型主角/当前坐标标记，与右下定位按钮对应；不增加任务/路线装饰层。
- 统一底栏，默认首页五入口均为图标+文字，中间为抢单。

## 4. 骑手

**方向**：将大人物海报式列表改为可扫描的双列信息卡，二三十名骑手约两三屏浏览完。

- 采用双列卡片概览，卡片约140逻辑高、行间距约10；内容视口可见约5–6行，即约10–12人；31人的16行总长约2.8个内容视口。不得靠缩成一屏31人实现目标。
- 头像为姓名区旁的小头像，约48–56逻辑大小；人物仍可辨认。信息和动作决定卡片高度，不保留大幅半身图。
- 首位“我”：姓名/Lv.5、经验810/945及进度条、配置车辆；主角无金币升级按钮。
- 已招募NPC：姓名/等级/状态、今日收入、作业耗时与收入加成、配置车辆与升级骑手。阿航样例为Lv.1、配送中、今日30、作业耗时100%、收入加成+0%、升级8金币。
- 未招募：姓名/等级、短介绍、骑手属性、招募费用；无车辆信息。小夏样例110金币。
- 用“作业耗时100%”明确骑手固定取送操作的基准耗时，不把它伪装为车辆道路速度；点击属性可解释，列表不堆说明。
- 升级动作先展示等级/收益/耗时的前后变化与费用，再确认消费。概览只保留入口，避免把升级详情常驻每张卡。
- 为证明长列表排布，可额外给出**后期密度示意**，其姓名/等级/状态只作为排版样例，不改正式名册、价格或存档。当前县城实际只有我、阿航、小夏的样例不能伪称已招满。

## 5. 车辆

**方向**：一个固定的联动预览区＋下方可持续选择的车型宫格。

- 上部约占内容区40%：选中车型大图、完整名称/等级、已拥有数、新购Lv.1速度/容量/收入加成、购买价格与购买按钮。
- 下部三列车型选择宫格，每格只放车型缩略图、档位/短名称、拥有或锁定标识；不复制上方整套参数和购买按钮。允许宫格合理滚动，不要求十车完整详情同屏。
- 点宫格立即替换上部车型图、名称、参数、拥有数、价格和解锁说明。始终在本页原位预览，不弹出大窗、不跳新页。
- 默认选中C级作为可购买示意：品牌电动车，拥有1辆，新购Lv.1速度17km/h、容量10kg、收入加成+32%、320金币。
- 提供B级锁定示意：大箱摩托车，拥有0辆，24km/h、19kg、+75%、680金币；明确“解锁城市后可购买”，按钮禁止。钱够不等于地图资格达标。
- 全部十档车型均可浏览，锁定车也能预览大图和完整参数。不能隐藏锁定车型或模糊其插画。
- 上方是唯一购买区。商城不承担具体车辆实例选择/升级；它们仍在骑手的配置车辆内页。
- 保留既有车型母版：D+黄黑方灯、C奶白黄、C+蓝黄风挡、B黑色载货摩托、B+红黑运动、A白藏蓝金、S藏蓝金、SS黄金轮式、SSS白金飞行。不得互换车型。

## 6. 订单大厅

**方向**：弱化大餐图，让选单信息和已选汇总优先。

- 顶部标题/金币/体力规格统一；刷新显示“剩余2次”，避免2/2不知是已用还是剩余。
- 餐图缩为小缩略图，标题、金额、重量、时限、取送位置可快速扫描。保留易损标识。
- **用户最新纠正：只有一个连续向下滑动的订单列表，不设“全部订单/已选订单”tab，也没有页码或左右翻页按钮。** 已选与未选在同一列表通过勾选状态区分，列表继续向下浏览；已选汇总固定在底部。
- 保留四单2/2/2/3kg，总重9/11kg、预计64金币，去选择路线；不恢复固定三单上限。
- 已选数/载重/预计收入/路线按钮固定在底部内容区，和底栏之间有明确安全间距。

## 7. 地图

**方向**：保留五张独立图片卡，加强地区辨识并避免底部遮挡。

- 县城、城市、省会、一线、国际都会各一张独立大图；不画连续世界地图。
- 每图只叠名称、当前/未解锁、费用/解锁动作；卡片不重新堆经营条件文字。
- 县城低中层山景、城市普通高楼街区、省会行政轴线/宽阔大道、一线密集高楼与立体交通、国际都会滨水天际线；保持原风格与颜色，不以增加蓝色区分高级地图。
- 五图可以合理滚动；最后一图完全滚出后有足够底部留白，不被橙圆盖住。
- 地图解锁失败的具体原因放在点击后的简短状态反馈中，金币不足与经营资格不足分别说明；不取消原资格规则。

## 8. 账单

**用户最新纠正**：无需分“今日”和“累计”，直接一张账单页面。取消切换控件，不制作两个分开的视图。

- 一页从上到下为今日经营、近7日配送收入、累计账目、累计支出分类，用小标题标明统计口径；不以今日选中态包裹累计内容。
- 今日经营：配送收入222、补给支出5、配送净赚217；15单（主角12/骑手3）、主角里程24km、在线38分钟。
- 近7日配送收入：0/58/104/176/240/333/222，总计1133。
- 累计账目：累计配送1133、任务奖励57、累计支出610、余额680、初始100；支出分类招募100/买车470/车辆升级15/补给25/骑手升级0/地图解锁0。
- 用金币表达金额，不把账单标题/数字做得比其他页更大；降低重复边框和重复卡片的视觉噪音，但保持现有颜色。
- 如内容需要，允许在同一页面合理滚动，不靠挤小字体强塞一屏；只交一张账单主稿。

## 9. 核对与交付

- 六个主页面＋车辆锁定态；骑手密度示意明确标注样例属性。账单只有一张页面，不再出今日/累计切换态。
- 每个原生输出归档来源、完整提示词、参考图、尺寸、SHA256和人工静态查看结论；保留旧版本，不覆盖。
- 不将静态图核对称为游戏测试，不声称已实现交互或通过用户体验验收。
