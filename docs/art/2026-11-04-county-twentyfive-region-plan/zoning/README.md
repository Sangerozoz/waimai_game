# 用户三层范围在25区制作中的落实

2026-11-04用户再次交回标注图并强调：红是地图边界、蓝是城市边界、绿是城区；红蓝之间绿地山脉，蓝绿之间郊区，绿内繁华城区。这与11-02已保存规则一致，不是新改边界。棕框仍只是旧底图放大索引，不作生产/经营边界。

原始依据：`docs/art/2026-11-02-county-zoning/selection.json`及同目录用户原图。25区分格不改变三层范围；一个TR区可能跨多种分区，不能整张统一做成城区，也不能因为区名叫“郊区”就忽略其中绿框内的部分。

当前问题：几何数据保留了三框，但此前生成底稿只给道路/足迹，提示词又要求填满可建设空地和重复施加同类城市设施，导致实际画面未充分拉开城区与郊区密度。图4又借用了完整邻图构图。这是制作落实缺口，不是声称边界已从数据丢失或用户重新指定。

- **绿框内繁华城区**：更密连续街墙、多层/适度中高层、办公商业公共设施更集中，仍保留原路、入口与必要小绿地；不能只靠画几个高楼当城区。
- **蓝框内绿框外郊区**：明显更疏、更多低层、独立/联排住宅、院落、社区设施、运动游乐/工坊等较大地块；留的是有设计的院落/绿地/步行空间，不是无内容空白或满地公寓。不要每区都要求相同50%住宅或全套地标。
- **红框内蓝框外外围景观**：绿地、树林、山丘山脉，原水系/背景地形保持；不做经营街区，不新增取送点，不允许完整配送路线借道。原city外围建筑/道路只读作来源，不因此恢复城市开发。

[zone-overlap.json](zone-overlap.json)按原矩形逐区计算core/render与三种范围的交集。只是几何参考，未扣水路面积，也不是实际成图建筑面积/绿量/50%住宅验证。原用户允许近似，本轮不扩缩边界。

当前TR-34的render约39.1%落繁华城区、60.9%落郊区，全部在蓝框内，不应凭空增加本图外围山脉。下一版底稿明确标出该过渡，先纠正本图原路与密度分区再扩量。前3张视觉方向认可不等于三层密度表现或原路配准已通过，后续整体收口仍需按本矩形核对。

住宅约50%继续作为蓝框内规划街区用地总体目标，红蓝之间自然背景不参与该比例。地面绿植“相对减约10%”针对原城区候选的种植密度，不用于清掉用户定义的外围树林/山脉。无屋顶种植要求保持。

本目录只计算源资料与记录生产约束，不改源city/道路、引擎、正式业务或存档，不触发游戏测试。
