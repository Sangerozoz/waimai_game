# 拼接反馈诊断与降错方案（仅分析）

用户本轮要求先分析，不生图/改图/改拼接代码，不启用路线或游戏测试。25图单张画面认可保留，新增拼接缺陷单独记录。反馈截图编号1～10与地图图号01～25严格区分。十张原附件原样保存，逐条见issues.json。

## 已有证据

1. assembly/prepare.py直接把2048底稿的比例/边距按1254图片尺寸换算，并没有根据生成原图里的实际路口测量变换。guide-record也明确geometryMeasuredAgainstGeneratedImage=false。名义底稿坐标一致不能证明成图一致。
2. 同脚本用core地面多边形给每张整图clip-path，没有楼体轮廓或对象归属。建筑立面/屋顶/树冠可以伸出地面格子，故会被机械截断。关闭裁切又会遇到不透明底覆盖、重复内容，不能当最终修复。
3. 图13(TR21)底稿与原生图对照：原图明显增加多条小街巷、庭院/建筑，故存在生成内容偏离底稿，不能全部归因摆放误差。图01也未经成图配准，不能默认它绝对正确。以源city区分哪侧错。
4. 25区边缘虽有64m共同地面，生成输入没有同一份锁定的已绘边界像素；两区对共同建筑/河道独立重画。重叠范围相同不等于重叠内容相同。
5. 图02圈注位置在原生图中也有庞大建筑体量；道路覆盖需对照源路识别是绘制占路还是屋顶投影遮挡。任一情况都不是移动邻图能修复的单纯接缝。

生成服务内部机制未经证实；以上为输入、输出、代码层面的证据与限制。

## 原因对应措施

- 全图平移/缩放/旋转偏差：以源路口、桥头等分布控制点测成图配准，额外点复核；先测再裁，不能只对齐一条边。局部路形不一致不能用强扭整图冒充一致。
- 路宽/路河类型错误、路被楼吞：原city道路/水域为唯一结构真值。后续生产使用同一结构母底，AI负责建筑/景观表现，最终用可控图层/人工定点修正保证道路廊道与河岸；有错误旧路/楼时先移除或重绘冲突内容，不能只叠一条路盖屋顶。只凭“保留原路”提示词不能承诺锁定。
- 跨缝楼变另一栋：共同带的同一对象只保留一次完整绘制并指定归属；不能把两份不一致的楼各裁一半。必要时用包含两侧必要接头的局部联合修订，不附完整邻区诱发构图借用。图中已有楼但两图均不完整则需要一次完整对象重绘。
- 硬裁建筑：将机械core裁切换为按路边/空地/河岸等选择的可调整归属线，绕过完整建筑及阴影；按实际楼体投影跨度保留足够重叠，不能只加halo期待自动解决。地面与高于地面楼体的归属分开处理。羽化仅用于草地/纹理，不用于双路/双楼错配。
- 城市边缘骤变：先在全县坐标上规划连续的密度过渡带，再分区渲染；保留用户允许的蓝外无导航零散背景住宅。不能以蓝框直线/分块边界作为末排房与树林分界。

## 推荐路线与对比

A只改拼接参数：保留已有图片，适合真正的整体偏移和切楼；不能修类型转换/占路/同物异形。
B修拼接归属并建立确定的道路水域结构，局部联合修边界：推荐；保留25图主体，结构真值唯一，对错处定点修。原生编辑边界仍需核验，只有被保护/复用或确定性绘制的最终像素才是硬约束。
C全25图重生：成本高且重复独立生成仍会复发，无证据证明更可靠，目前不选。

## 推荐最小验证顺序（尚未执行）

先图01—图13共享带，联查图12/图15等相邻接头：源路/河种类和宽度标清→测两侧成图配准→指定完整建筑归属→只修必要结构与过渡带。看同一处是否同时解决路宽突变、路河混淆、换楼/裁楼。图02单独验证占路建筑，先分清投影遮挡与画错。验证成立再按40条共享边推广，每次改动检查本区全部邻边和四区交点，避免修一边坏另一边。
