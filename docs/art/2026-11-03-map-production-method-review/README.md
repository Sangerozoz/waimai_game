## 从这张图能观察到什么

学校是教学楼、操场、球场、围栏、绿地、入口的完整组合，公园有水面、步道、植被与边界；道路、人行道、种植带与建筑距离有连贯关系。整景一次构图能在一个范围内协调密度、材料与光影，这是单件PNG摆放后需要重新补足的场景设计工作。

图里也烘焙了汽车/公交等内容。静态图上的车不会自行变成可运动实例；建筑和树冠遮住的地面没有完整可用信息；可见道路不等于有通行方向、连接节点和合法取送点的数据。全局好看不能证明每个路口几何、每栋门点、透视和阴影都准确。

## 两种方法的工程取舍

| 方式 | 初始视觉 | 进入游戏后的主要成本 | 适用范围 |
|---|---|---|---|
| 独立生成整区域，拼接后再定路线 | 容易获得完整构图 | 边缘道路/光照接缝、统一比例、去除烘焙动态物、遮挡拆分、重画冲突路段 | 静态总览/远景；布局可重新设计的小地图 |
| 逐栋/逐树生成独立图，逐件搭建 | 容易取得单件细节 | 相机/比例/朝向/光向一致性、树池与地面场景设计、重复与组合成本 | 稳定的统一素材库；需要频繁改变布局的地图 |
| 先路网，按完整地块制作场景，动态内容独立 | 把构图统一在地块范围内 | 受控边缘、跨块修整、遮挡对象拆分/标注、动态接入 | 当前固定斜俯视配送游戏的优先候选 |

表中成本高低是针对本项目的工程判断，不是已测生产工时。整景拼接不能保证任意生成都能无缝；大地块也不能以一张不可分层的PNG解决骑手前后遮挡。

## 成熟团队的做法

通常先建立可重复制作标准：玩法所需路网和地块、固定镜头、单位尺度、路宽、门点、材质与光照规范。随后用统一资源库和编辑工具搭街区，必要的关键场景单独设计；最终表现可以是实时3D，也可以由3D场景按固定镜头渲染成分层2D图片，再人工精修和导入引擎。选择取决于美术人员、镜头与动态变化需求，不要求所有项目都采用某一种引擎或表现。

一手实例：[Factorio 2016年官方美术流程](https://www.factorio.com/blog/post/fff-146)公开了概念/技术要求、Blender建模、分层输出、Photoshop后期及自动打包的过程；其价值是可修改源和可重复渲染，不是“只要3D就自动好看”。此例是当年公开流程，未推断该团队目前全部工具仍完全相同。

我们此前的程序盒子楼/不成熟3D样板不代表专业3D美术生产线的能力，也不构成本次自动恢复3D开发的理由。当前逐件AI生图方案低估了场景拼合、同机位和可交互资产加工的成本；更多生成次数不能代替这套标准。

## 针对一人＋AI的建议

建议采用“先路网约束，再完整地块美术，最后动态与遮挡接入”的混合流程，保持固定镜头与受控缩放。

1. **锁逻辑底稿。** 对当前项目沿已确认路网和三层边界，把道路、路口、地块边界和合法入口投影成美术底稿。AI图偏离可行驶区域时修画面，不未经批准追着图片改经营路网。全新地图若允许重定布局，可以先整景探索，但最后仍须把美术与可行驶图一起修正到一致。
2. **把美术单元扩大到完整地块。** 例如一组店铺带门前铺装/遮阳/树池，或一个小区带入口/院落/围栏，或一座完整公园。让AI在一个构图里处理建筑、种植区、材料和静态光影；可重复或互动道具再独立。街区交界尽量沿低矮的人行道/路缘等可控制边缘，跨界高楼/树冠另设归属与重叠区。
3. **统一处理路网接口。** 跨区主道路与路口继续由统一几何/铺装或可控底稿决定，不让每张整景自由发明接头。相邻图使用相同尺寸、相同镜头、明确的边缘锚点及邻图参考，并预留修整区；不能靠提示词保证精确接缝。
4. **准备实际运行层。** 地面/静态地面影、按遮挡关系拆开的楼体与树冠、动态骑手与交通、订单/地点标记分别处理。不是把整张街区作为永远在玩家上面的前景。需要实际提取/补画/标注遮挡对象和接地锚点，AI不会自动交出可用深度。道路行驶车辆/人物从底图移出；固定停放车辆可按用途保留为背景。动态角色影与静态光向一致。
5. **先制作一个代表性街角。** 建议1个路口＋两侧完整地块＋骑手一段可见路线，以实际手机玩法视野评估清晰度、画质、门点/道路对位与前后遮挡。其目的是证明生产方法，不能用缩小的整县海报冒充近景画质。只有代表样板成立再扩。游戏测试仍按用户明确“阶段完成”后集中安排。
6. **按合格场景成本估全图。** 记录一块完整场景从生成、修图、分层、标注到引擎接入的实际工时与返工次数，再估全县成本。生成一张图的分钟数不等于交付一块可玩地图的成本；当前没有数据支持承诺固定几天完成整县或固定能省多少百分比。

[Tiled官方图层文档](https://doc.mapeditor.org/en/stable/manual/layers/)区分图块、图像和对象图层，支持把视觉与独立对象资料分别组织；这只能证明组织方式可行，不能证明AI整景自动包含导航/遮挡数据。[Cocos 3.8 TiledMap API](https://docs.cocos.com/creator/3.8/api/en/class/TiledMap)有TMX显示与裁切相关接口；本建议不要求迁移当前工程到Tiled，也不以通用引擎能力证明当前具体画面已达标。

## 质量与成本的边界

固定镜头、静态城市和大地块美术能减少一人制作的重复拼装工作。代价是自由转视角、随时拆改每栋建筑、真实变化的太阳光/跨建筑投影、极近放大等能力会更难；如产品以后把这些作为核心体验，统一3D资源库的长期收益会提高。此为未来体验取舍说明，不在本次擅自新增/删除产品功能。

若追求附件同等完整度，仍需承担场景修整和可交互分层的美术工作，可由本人、AI辅助或有限外包完成。AI能加快候选和局部修订，不能把这些环节的成本计成零。

**待讨论的制作建议：** 将主生产单元从单件独立素材提升到完整地块，以现有路网约束制作一个可运行的代表街角。尚未授权切换，不继续生成整县图，也不取消/覆盖既有素材和工程。
