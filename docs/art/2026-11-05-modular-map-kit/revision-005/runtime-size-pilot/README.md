[实际小纹理Cocos](viewer/) · [运行截图](engine-small-textures.jpg) · [详细统计](resource-report.json) · [新灯400运行图](examples/new-near-lamp-400.png)

## 当前结论

工具返回的原生图通常1254×1254，也有1024×1536/1265×1243等。原生画布不是每件物体必须使用的运行尺寸。母版保留归档，运行版单独裁边、缩小、校正锚点并按引用导出，不打包整个美术历史目录。

本次真实导出：建筑/重复地材长边上限600；树、灯、骑手上限400，非强制正方形。示例：B01为479×600、T01为290×400，新近侧灯为187×400。原始像素文件与Tiled地图没有修改。

8张现用图片的PNG总量从11,265,368字节降到2,016,000字节，减少约82.1%。原旧预览有22张散装PNG、31,887,680字节，其中包含未引用历史图；新运行目录只含实际使用的8个文件。以上都不是整个游戏包大小。

同8张唯一图片的基础RGBA解码量估算从约47.99MiB降到6.14MiB；不含mip、驱动、引擎、地面画布和UI，不冒充真机显存/加载时间实测。运行已读回8个唯一图像载入、6个共享原生SpriteFrame和2个画布Frame。三株同款树和重复灯不再各新建一份相同贴图。

## 导出方法与限制

- 完整母版与来源SHA保留，派生图明确标记runtime，绝不把缩图称为新的原生输出。
- 以主要alpha连通内容分析边界并留12原图像素边距，避免少量漂浮alpha噪点迫使细路灯占整张方图。裁切范围内保留原alpha后做预乘alpha重采样。
- 同步anchorUV、骑手轮接地点、opaqueBoundsUV与地面多边形；静态对象使用独立worldSizeUnits保持物理大小/位置，不能因为PNG缩小就把楼或树缩小。
- 修复派生演示壳按实例ID重复解码/创建SpriteFrame的问题，按文件SHA共享图像与Frame。
- 这只是同一revision-004街段的尺寸对比，**旧灯向尚未在这里替换**，不冒充revision-005新街区。地材降采样后的网格观感也有差异，尚未作风格验收。
- 当前普通近景已实际显示并保存截图；最终游戏最大缩放和设备DPR预算未冻结，不能据一次画面保证所有极近景都清晰。大型特殊建筑按实际显示需求单独评估，不默认全用1254。
- 未运行游戏阶段测试/性能基准，不改业务/UI/经济/存档；这批导出参数不是用户已完成视觉验收。
