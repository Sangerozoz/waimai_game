# 美术场景意图与源数据分层：小范围复合场地合同

本合同是地图PM在已有“参考认可25图、丰富场景、素材搭城”授权内的制作决定，不是产品/经营/导航改动，也不是批量准入。依据：placement-capacity-audit/REPORT.md；父已复读plan_fifth.py与assemble_fifth.py的真实分支并复核45源统计。

## 1. 原始未知不伪造，美术意图另列

原city.buildings只有几何、没有已证实的每楼用途/门/业务绑定时，保留`originalSemanticStatus: unknown`。不得把旧metadata缺记录写成“空间不够”或“用户禁止规划”。可依据已确认蓝绿分区、实际周边和认可25图，显式增加`scenicProgramme`及`programmeEvidence`，标为本次PM美术设计，不声称源建筑原来就是商店/住宅/工坊。原city/landuse原文件/POI名称与node/经营类型/停靠点/路线/存档均不写，不因此新增经营地址。

## 2. 本轮只做静态小试点

先核7处被旧metadata缺失直接延期的源586、125、590、588、430、580、429的真实空间。父只读面积/朝向包络初算中590约407.25平方米，可能适合优先验证；这不是足迹可行认证或承诺一定放得下。优先找一个未绑定、未预留源做**一场景两模块**；必要时最多两个实际相邻源联合一场景，不跨原道路凭空圈大区，不能把大片未画原楼一概豁免。若确不成立，提交明确失败证据与可行单模块子集，不强凑。

只用当前已准入B01～B08的少量不同体量，正比例只用既有合理尺度，不能把大楼缩成小盒子。B12/B13/T05本轮原有有限比较不因此扩大，B09～B11/T04继续hold。不生新图。

## 3. 显式场景所有权，不绕过防重

一个sceneId明确持有真实sourceIndices/sourcePolygonsMap集合与moduleIds。每模块有独立persistentId、sceneId、真门、实际候选足迹/入口/单次世界尺寸。相同源只允许在**同一个显式场景**的模块间共享引用；不同场景不得重复占用源。旧81绑定及所有既有对象/地面不改。

源数按场景源集合并集计，模块数单独计；例如一源两模块仍uniqueSourceCount=1、moduleCount=2，不能宣称两源或两个经营点。多源一景也不按模块重复累计源。重复模块ID、跨场景源重用、旧已绑定源碰撞继续拒绝；不得仅删除assigned/source去重断言。旧单模块输入仍兼容、旧记录不回写。

## 4. 物理与编辑边界不松

原邻源实体、原路水/蓝边、原POI与旧门路/旧场地/已有sprite仍按当前安全规则保护。只有本场景明确拥有的源载体可在候选艺术替换中豁免；同场景模块之间、真门/路径之间仍查实体碰撞，不因同源豁免彼此。新场景内铺地可有真实相接/叠层关系，但不能用地面覆盖遮住实体、门路或车道。

本合同**没有**允许全局放开旧草坪/院坪或重划旧497面。先独立静态证明，不修改共享导入器，不直接接入。若需要旧场地接边编辑，必须单列具体面/字段/理由及其他独立失败项，由PM另批，不得悄悄放宽全局。

## 5. 发布门禁

静态产物必须给实际脚线/真实门、同源模块净距、有限庭院/连接、完整原路和源SHA、场景/源/模块三种计数与明确不确定性。独立复审通过后，才能给共享导入器作者一个受限scene级合同适配任务；不把静态候选或合同落盘记作已显示。接入时始终复核市场生活层等真实最新增量，不用历史快照重置地图。
