## 2 跨资源一致性

- 日系青春都市动漫：清楚但不过重的轮廓线、柔和厚涂明暗、自然成人比例、城市日常材质，有生活使用感；不用Q版、塑料3D、照片写实脸或霸总幻想造型。
- 静态美术光线统一左上暖光，阴影柔和；地图顶视图不烘焙大范围发光/地面背景。人物可保留适度轮廓光，避开与地图一起旋转的大光晕。
- 色彩：暖白/炭灰作为界面底与文字，外卖橙为品牌识别；按钮浅香槟金至暖橙，次按钮深棕与细金边。低饱和绿地、蓝绿水域、米灰道路、暖灰建筑。语义：转单/成功绿、取消/风险红、禁用灰。
- UI以克制细金边、柔和渐变、小菱形端饰形成统一语言，图标跟随用途简化厚涂；不把宣传插画的高细节强塞入小图标。地图仍真实俯视路网，不改斜视街景。
- 动态标题、金额、倒计时、等级、评价、按钮文字全由引擎绘制，不烘焙进图。不使用假文字、水印、商标。

## 3 资源规范

| 类别 | 制作要求 |
|---|---|
| 主角全身/成长变体 | 参考已接受母版+图5；2:3竖图，建议1024×1536，头脚完整和安全边，同人一致；成长服装分阶段制作 |
| 主角头像 | 优先用母版裁切/引擎取图；独立生成时必须附母版，脸发一致，头肩近景，适配圆形安全区 |
| 地图车辆 | 2:3透明PNG，严格正交顶视、车头向上；清晰轮廓和统一比例锚点；不以侧图旋转替代，不烘焙地面大影 |
| 展示车辆 | 同车型独立侧/三分之四展示视角，与顶视颜色/车体/箱体一致，各档可辨 |
| 餐品 | 统一三分之四俯视、固定光源、真实食物色彩、简洁餐盒/器皿，透明底；实际图像必须和目录餐品匹配 |
| 功能/状态图标 | 统一透视/线条/暖光，形状优先，简洁留白；功能图标与状态色统一，不套旧卡通图集 |
| 面板/按钮 | 优先公共代码组件；若需要位图则可九宫格拉伸、边角安全、无文字。不能每个页面独立生成一套风格 |
| 地图建筑/店铺/站点 | 顶视地图与展示插画用途分开；保留真实几何/地点位置，暖灰屋顶、柔和投影，图标不遮路径 |
| 后期NPC/城市/天气/收藏/宣传 | 同上述身份/材质/色彩规则；玩法实际实现后按真实用途出图，宣传不虚构功能 |

## 4 可直接复用的提示词前缀

“为《送外卖》制作原创游戏资产。附件图5仅为绘画、材质和光影参考；有角色/车型母版时，以母版作为身份与结构依据。日系青春都市动漫厚涂，清晰克制线条、自然比例、左上暖光、柔和阴影、都市生活质感，外卖橙/炭灰/暖白协调。严格遵守本次指定视角、用途与画幅。无文字、无商标、无水印、无UI；透明背景PNG（需要场景背景的任务除外）。不要Q版、塑料3D、摄影脸、幻想宝石边框或重霓虹。”

每批在此前缀后追加：资源ID/用途、身份或结构母版、视角、数量、尺寸、安全边、禁止项。不要只说“动漫风”而丢失锚点。

## 5 制作与交付流程

PM按替换台账选小批 → 美术给完整提示词与实际应附参考 → 用户浏览器生成并交回原图 → 保存不可覆盖原图及SHA → 核用途/透明/视角与身份 → 必要用户确认母版 → 开发接入并构建。

母版确认后的同人/同车变体复用已接受图片，不重复重设计。每项独立记：待制作、用户已交图、已接受、待处理、已接入、待阶段测试、用户体验确认。未更新资源必须明确列出；旧素材留回退但最终展示不能漏换。过程不派测试、不跑渲染矩阵；用户明确“阶段完成”再集中检查全界面混风、边界和功能。
