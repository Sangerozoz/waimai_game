## PM建议，尚非已验证生产线

优先考虑固定斜俯视的二维独立素材＋道路/河流铺装模块＋独立路网/取送点数据。整栋建筑在图片中画完整体积、窗/屋顶/阴影；引擎负责摆放、分层、加载和动态角色，不再临时挤出通用盒体。公园/学校/小区可做完整场地模块再加少量道具，避免整县逐株摆树又缺乏场景设计。

路网和经营边界沿原坐标保留，以原路网制作道路底稿并安排素材；生成图有道路不能自动成为可行驶路径。道路/河流需要直段、弯段、交口、桥/岸等可接缝模块及适配，不可自由生图后假设精准吻合。建筑占地、入口、脚点与遮挡范围需独立标注；建筑图片不能随意二维旋转来改变建筑朝向，应制作所需朝向版本。固定镜头拖动/有限缩放可做，自由转视角不适合固定单向素材。

每件交付应为可独立使用的透明原图，附统一机位、米制比例、光向/阴影、地面锚点、占地和前后层说明；一张素材大全展示图不等于可用素材包。人物/车需方向帧，建筑/树需处理与骑手的前后遮挡。图片不无限放大，地图分块与视口加载另做预算。

推荐先小批资产：3栋独立建筑、2种地面树、一组连续道路/人行道、1辆静态车和少量道具，在一个原街角实际拼合，再看透视/比例/接缝/遮挡/画风。此处仅记录方法讨论与建议，未启动新生图、改代码或铺全县；当前3D样板保留为技术对照，不默认继续扩展。

引擎能力依据：Cocos 3.8的[Sprite](https://docs.cocos.com/creator/3.8/manual/en/ui-system/components/editor/sprite.html)可显示图片；[Tiled层说明](https://docs.mapeditor.org/en/stable/manual/layers/)区分图像、对象、图块与路径数据，支持视觉层与逻辑资料分开组织。具体本项目拼装工作流仍须以实际小样证明，不因为通用引擎支持就承诺画面达标。
