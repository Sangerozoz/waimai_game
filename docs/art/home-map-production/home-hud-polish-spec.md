# HOME-POLISH-1101 首页HUD制作规格

2026-11-01。状态：制作建议已落文档，未实现、未测试、未做渲染或用户视觉验收。输入为已认可的`docs/art/home-map-concept/home-map-screen-v1.png`、本目录`asset-handoff.md`、精修计划Task3，以及当前`MapSample.ts`的header/layoutPlayerHeader/controls/navigation只读源码。沿用现有首页方向，无新图片需求。

## 坐标与组合

以下为720宽设计坐标，使用**安全区内左上角向右/向下**的局部坐标描述，开发转换为Cocos坐标。设H=1280+screenExtra，M=现有outerMargin()/pageMargin(H)所换算的16CSSpx，L=safeInsets.left+M，R=720-safeInsets.right-M，T=safeInsets.top+M，可用宽W=R-L。不要把M固定为16设计像素；基准示意M约32、W约656。HeaderGroup已处理screenExtra/2与safeInsets.top，转换时只能计入一次安全区与长屏偏移。

| 组件 | 明确制作建议（设计单位） |
|---|---|
| 左上人物卡 | 左上(L,T)，宽252、高108，圆角18；暖白完整承托将头像、名称、等级/经验组合成一张卡 |
| 头像 | 卡内左12、上12，框84×84；复用已接受avatar，保比例与脸部完整，不随图像异步实际宽度改变整卡宽度 |
| 品牌名 | 卡内左108、上13，文本区132×30，字号26、加粗炭灰；默认固定“澄川骑手” |
| 等级 | 卡内左108、上47，文本区132×26，字号24、加粗；动态Lv.player.level，单行 |
| 经验 | 卡内左108、上82，宽132、高8、圆角4；浅米灰轨道、暖橙进度；直接使用现有experienceProgress(player.experience)，等级与条分离，不在填充条上叠等级字 |
| 区域牌 | 卡下间距10，左缘与人物卡一致，宽132、高40，圆角20；深炭灰底，已有定位图形或简洁引擎标记24，间距6，“县城”字号23暖白 |
| 右侧数值组 | 右缘固定R、顶缘T+4，与人物卡水平间距至少12；金币在左、评价在右，两胶囊间距10；高度56、圆角28 |

人物卡底色#FFF3DF，文字#292C2B；描边1单位#C4A878、低透明暖灰柔影向右下偏移(2,3)、柔边约6。区域牌#303331、字#FFF5E6。面板内细节靠留白和轻微明暗形成层次，避免粗黑描边、强金光或多层大底板压住地图。卡内头像点击继续原openRider门禁逻辑；不把整个Header做成拦截地图拖动的大热区。

品牌名只是现有显示品牌，区域牌只写“县城”；当前没有自定义姓名/县名字段，不新增或写入身份存档，不照抄概念里的具体地名。等级、进度、余额、评价均读现有真实数据；概念中的Lv.5/1872.95/100为样例。

## 紧凑胶囊与窄屏顺序

每个胶囊按实际字体度量，宽=左右内边距各12+图标32+间距6+文字宽。数字字号26、加粗，单行；图标与数字作为一个内容组居中，图标右侧距首字6，不能把图标固定在宽底板左端、数字另行居中造成空洞。金币复用coin，评价复用heart；金额沿现有格式与精度，不附第二个货币符号或“金币”长标签。数字增长时右侧组保持右对齐、向左扩展。

1. 先按252宽人物卡、至少12横向间隔与右侧剩余宽计算；两胶囊真实期望宽之和加10能容纳才同排。
2. 放不下时右侧改为上下两行，金币上、评价下，间距8，均靠R，宽按各自内容计算；不得让评价越过人物卡。该分支在普通长余额时即可触发，无须强撑概念同排。
3. 仍过窄时人物卡收至224：头像72×72、内边距10、名称区122，姓名字号24，卡高104；头像与文字间距10，进度宽122。保人物组合、品牌名和真实等级。右列数字可由26降至22，图标32降至28，横内边距12降至8，间距最低4。等级24降至20以容纳大等级，进度仍独立。
4. 单个余额在右列仍无法完整显示时，金币与评价整组移到区域牌下方一条独立行（距区域牌底10，使用完整W），优先两胶囊同排，仍不足则上下排列。人物卡与区域牌不被覆盖。极端长数字可继续增加专属行宽/高度并使用该标签局部SHRINK，保完整原值、不换行、不截断、不用万/亿替代精度；不改全局readable。HeaderClearance必须随最终实际边界变化。

窄屏优先级：安全区与可操作热区→真实金额/评价与等级完整→人物卡组合与区域牌→装饰柔影/间距。先换行布局再缩字号；不得隐藏入口、把数字挤入头像或将胶囊伸出安全边。长屏只将顶部组合锚在实际安全顶，底部控件锚在实际安全底，中间新增高度留给地图，不按屏高放大卡片。

## 配送状态、地图控件与底栏

- 活动中小白暂停沿当前canPauseDelivery、半尺寸绘制与独立触区规则。放人物卡区域牌下方，左侧可见底板边缘对齐L，距区域牌底12；保持白色Ⅱ和现有触区，不恢复大图标。独立触区与区域牌、数值行、配送状态的可见框至少间隔8；如数值降到全宽额外行，暂停移至该行下方，不能盖住它。配送状态沿当前真实阶段显示，必要时放在顶部所有组合下方，避免与暂停触区相交。
- HeaderClearance取本轮实际可见卡、区域牌、胶囊、暂停触区与配送状态的联合最低边，再加M；不能继续仅用头像高度/经验条barY推算。仅参与当前active节点，头像异步加载或resize后重算，不占用整片透明地图为输入遮罩。
- 站点/定位使用相同100×100可见适配框，图像contain，不拉伸；左右边缘分别锚L/R，框底在同一地图控制基线。点击目标各自至少现有热区及44CSSpx要求，不相互侵占。当前站点标签“站点”置框下，定位若无标签也不把框移低；按图框底对齐，不按含文字总框或源PNG透明画布对齐。保灰站点现有表现与状态。异步图加载后仍保持同框/同底线。
- 无订单首页控制框底线建议位于导航最高可见边上方24；活动中沿既有订单sheet上沿留空并保持现有规划态隐藏规则，不修改订单流程。缩短地图空间时优先收紧顶部装饰间距，保热区和sheet主动作。
- 底栏继续骑手、车辆、抢单/订单、地图、账单五入口及原行为。深炭灰承托、细金上沿、暖白标签，中央沿现有145.6橙色动作图与现有凸起关系；复用main-action-glossy与已有导航资源，无火焰。底板延伸到安全底，点击内容留在safeInsets内；不改已有五槽与中央动作防重叠布局。

## 开发交接边界

当前源码人物区仍按孤立avatar实际宽度布局，经验轨道与Lv叠在头像下方；人物卡名称/区域牌需新增引擎节点，不能只改底色。现胶囊按字符数估宽并允许多行，本规格要求实际字体度量、单行数值和分支重排。改动限定首页组合及实际clearance计算，复用头像/coin/heart/导航；暖白底、柔影、细边由引擎绘制，不从概念图裁底板，不改源图、存档或业务语义。

本文件仅为明确制作规格，未修改源码/导入资源，未开游戏、截图、渲染、测试或操作用户页面/存档；没有将建议数值登记为实现或视觉通过。
