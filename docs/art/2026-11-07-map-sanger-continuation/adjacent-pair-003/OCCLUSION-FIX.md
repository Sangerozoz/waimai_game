# 屋顶遮挡描路修正

原只读复核会话 `thr_978x3n893w` 指出：`W-h-0-2` 从 `(1050,82)` 到 `(1595,82)`，约 `x=1440–1480, y=82` 穿过右上高楼可见屋顶。旧绕行使用这条边，不能声称全程落在可见沥青。主会话查看完整原生及 `verification/occlusion-native-crop.png` 后复现；裁图从 W 原生 `[1360,25,1550,145]` 直接截取，190×120，逐像素一致，无重采样。

问题来自语义门禁缺失：旧图模型将35条围合结构边全部用于寻路；几何交叉、连通、最短路及TMJ坐标检查均不能判断屋顶后方路面的可见性。修复前的三项回归检查均失败，原输出保存在 `verification/occlusion-regression-before.json`。随后增加的旧绕行拒绝检查也在修复验证器前复现失败。

本次将这条边标记为 `navigationAllowed=false`、`surfaceObservation=roof-occluded-inference`。35边结构图继续保留12个围合面，其中 `B-05-04` 的北边明确含遮挡推定；独立可导航子图为24节点、34边、1分量、11有界面。结构面的数量不等于全部边均已实看可见沥青。

构建器的Dijkstra及验证器的独立Bellman-Ford均只接受明确允许导航的边。主路径仍为3158.369316876853px；再排除 `W-h-1-2` 后，绕行改走南侧，3973.6525698173054px，旧3933.6226464978863px路径被取代。两条新路径均显式记录排除 `W-h-0-2`。

三份TMJ将可导航描线与 `occluded-inferences` 独立分层，后者默认隐藏并保留禁导航属性。交互图默认道路层同样只有34条；打开遮挡推定开关也不会改变路径。受影响街坊点选时显示北侧边推定说明。验证器比较全部顶点、完整名称覆盖和属性，并核对图层默认可见性、推定边索引及路径允许状态。
