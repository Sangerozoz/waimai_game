## 2. 三层区域如何安排

三层框线位置不改，棕色原底图索引不参与。

### 绿框：繁华城区

- 北部以青禾社区及周边水岸形成社区/绿地节点，保留水域与既有道路，不将河渠盖成高楼。
- 东侧沿现有较直道路组织商住立面与小型办公/公寓；桥边咖啡、河畔小馆等原地点只用于定位，实际营业入口仍绑定原合法节点。
- 中部榕树街食堂周边作为首块制作样板；南侧以住宅和生活小店延续街区。
- 建筑建议以3–6层为主，少量节点可稍高；商铺沿街相对连续，保持县城尺度。通过窗型、层数、屋顶轮廓与招牌/雨棚形状区分，而不靠持续加蓝或新增大面积玻璃蓝楼。
- 数据缺少建筑的非道路地块必须安排明确用途，可沿既有补景规则放建筑、庭院、绿地、公园或学校等；避让原建筑、水域、道路和入口，装饰不自行增加经营点。

### 蓝绿之间：郊区

- 西侧：低密住宅/院落与沿路少量小店，贴合河渠和较曲折路网。
- 东侧：低层住区、小店与现有大地块衔接；保留既有水塘，主路沿线可有稍集中的2–4层商住节点。
- 北侧：现有城区向低层街区渐变，避免绿框边缘突然出现一堵建筑墙。
- 南侧：住宅、院落、草地和水岸间隔布置。建议以1–3层为主、间距大于城区，仍可配送。
- 绿框是密度与美术分区，不增加地图解锁门槛、道路禁行或收费。
- 较大的建筑间距用院落、绿地、公园或校园等完整场地衔接，不能解释为大片未制作空地。

### 红蓝之间：外围景观

- 北侧以林地与低山轮廓收边；东侧以缓坡/林带形成遮挡背景。
- 西侧沿既有河谷保留水系和绿地，南侧以草地、水岸和疏林过渡。
- 山体位置是布景建议，不伪称真实高程。现有底图外侧显示的道路/建筑不意味着继续制作这些经营街区。
- 蓝框外不生成取送点、不作为配送通道。地图红边缘还需按最终镜头角度设置可视保护距离，避免拖动/缩放露白；这不扩大经营范围。

### 全部地块都有内容

此项为2026-11-03用户新增的制作要求，从首块样板到后续扩展统一执行。先给剩余地块安排用途，再补齐建筑和场景；图中红色圈注只是空白示例，不是只处理圈内地块。公园/绿地可以有开阔草坪，但要形成有边界、步道或适量植物等可辨认内容，不能用大片无内容底色代替完成的地块。学校可由校舍、操场和绿化组成，属于场景用途，不自动增加玩法或经营地址。

“填满”针对可布置地块的场景完整性；道路、水系、必要通行空间和合法取送入口保留，不用建筑/树木覆盖。城区与郊区保持原密度差异，延续当前颜色、植物控制和屋顶不种树的要求。后续画面交付逐地块核对，不留下大片未制作底色。

## 3. 道路与边缘怎样收口

### 静态盘点口径

来源为原始city.json，不启动游戏。保留道路direction和speed>0条件，仅使用端点均在蓝框内的完整路段；本次矩形为凸区域，所以完整直线段也位于框内。交叉的画面线条不自动创建连接。

结果：3328个道路节点、6355条有向边记录；主要弱连通分量3229节点，其他10个分量99节点；与起点可往返的节点3155个。原始地点目录14处落在蓝框内，均在起点可往返范围内。

这些结论只回答当前分区下原始道路/原始地点的规划可用性。运行时prepareCity会生成/选择更多地址，后续需要重新按蓝框、合法入口及可往返分量筛选；不能把14误写为玩法数量上限，也不能认为旧动态目录自然全部有效。

### 主路与支路的处理建议

边界穿界路段98条，聚为79组，13组主路在图②中标号，完整清单见[CSV](boundary-crossings.csv)。

| 位置 | 优先查看 | 收口方向 |
| --- | --- | --- |
| 东侧 | B26、B34两组主路，B22/B40等支线 | 可行驶段在蓝框内最近合法转向/完整路口处结束；入口向内收，外部不保留暗示可驶入的长道路 |
| 南侧 | B53及B46/B49等 | 结合现有交叉口、住区边缘、水岸确定终点；不把道路直接画成穿山通道 |
| 西侧 | B75、B79及B62 | 优先保留圈内河岸道路和原有桥梁连接；圈外河谷仅背景，不允许借河西外路绕行 |
| 北侧 | B08、B16 | 沿完整街区或合适路口收边，与北郊到山林的景观过渡一起处理 |

79组不是79个新设施，不需要为每条支路新造门楼/路障。边界穿过半栋建筑时，应在圈内按整栋退让处理，保留原始几何记录，不劈半楼或擅自扩框。

不能从起点往返的支段暂不布置经营入口；若确需使用，再列出具体缺连接或单行冲突，提出小范围处理方案。不得以视觉近邻直接画线跨水/穿建筑“补通”，也不能把本次盘点称为已修复。

## 4. 首块样板：榕树街食堂—晴川广场

建议精修范围：世界坐标X −1720至−1340m，Y −240至200m，约380×440m/0.167平方公里，全部在绿框内。周边图只用于接续关系，不等于本批全幅精修。范围数据见[sample-layout.json](sample-layout.json)。

| 锚点 | 来源节点 | 地面坐标米 |
| --- | --- | --- |
| P 榕树街食堂 | 1623821046 | −1540.46，−129.99 |
| D 晴川广场 | 9657208284 | −1614.89，142.10 |

两处入口沿蓝框内原始道路的静态参考路线约424m，全部在本样板范围。保留单行方向后，反向回到起点的参考路网也在样板内，说明此处能覆盖单行/路口的衔接问题；**反向参考只用于选址，不新增送完返回起点的玩法要求。**

初始镜头占位约180×220m，仅用于平面排布，沿现有15m比例尺思路预留；最终斜俯视投影、设备遮挡和视野范围由显示样板收口，不能把这个占位当作已验证摄像机参数。

精修区有113个既有建筑轮廓中心，属于几何库存，不需要制作113张独立房屋图。第一批重点为起点临街店面、若干连续商住立面、转角与送达入口，其余普通楼宇用一致模块组织；不改真实占地以迁就生成图片。113处只是原始建筑库存，不能用它限制补景，也不能将其间无建筑记录的地块留白；按本轮要求安排完整场景内容。

## 5. 画面落地方法与统一规格

建议固定与认可首页相近的斜俯视方向，保留拖动/缩放，首块不做自由旋转镜头。美术视角目标已确认，具体2.5D实现仍是提案，不在本轮迁移游戏显示系统。

| 层 | 制作依据 | 关键要求 |
| --- | --- | --- |
| 地面/水域 | 原地块/水道边界 | 同世界坐标铺材质，保留水域，移动缩放不改变纹理相位 |
| 道路/路缘/人行道 | 同一路段节点、width、方向 | 图形与寻路共用几何；路口连续，桥面保持在水面上，不由生图决定道路位置 |
| 建筑 | 原占地、地面锚点、统一立面/屋顶模块 | 足点与占地对应，不能把任意整屋图拉伸成原轮廓；不在屋顶增加树木 |
| 入口 | 地点ID、合法道路节点、临街锚点 | 建筑外观与到达位置对应，不将屋顶中心或隔水最近点当入口 |
| 植物/小物 | 道路与建筑外的安全地块 | 冠幅/影子避路、避水、避入口；沿街受控，不机械铺满 |
| 骑手/车辆/路线 | 同一地面坐标和投影 | 路线沿路，车接地；转角不能平滑抄穿建筑；里程按地面米计算 |
| HUD/标签 | 认可页面规范 | 独立动态组件，保持当前配色和信息分工，不能把整屏概念图烘焙成UI |

所有素材记录画幅、主体框、地面足点/占地、朝向、世界尺寸和光照。光照沿认可母版，原角色/车型身份不改。建筑前景遮挡车辆时的具体显示策略在样板确定，不能用把导航线画到屋顶上掩盖坐标错误。
