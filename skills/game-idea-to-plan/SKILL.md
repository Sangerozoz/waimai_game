# 游戏想法到可执行计划

把想法逐层转成可验证的开发工作。方案覆盖全局，近期任务细化，远期保持粗粒度；通过证据修订方案。

## 先定位当前请求

| 用户当前需要 | 当前产出 |
| --- | --- |
| 了解方法、讨论拆解思路 | 解释相应层次和一个例子；保持讨论状态 |
| 把想法形成方案 | 概念说明、完整一局、范围与待验证问题 |
| 把方案拆成任务 | 阶段成果、依赖关系和近期任务卡 |
| 实施已经确认的计划 | 实现当前获准的工作，验证并反馈 |
| 接入或发布到 TapTap | 比较候选发行形态，核验当前能力后确定接入路径 |

用户只想讨论方法时，围绕方法展开，不替其锁定玩法、场景或技术栈。用户要求先讲某一层，就只深入那一层。暂停开发与继续讨论可以同时成立。

沿用已确认的要求和授权，只追问影响当前阶段的关键缺口。将信息标为「已确认 / 假设待验证 / 建议 / 待决定」。旧对话、参考作品与附件中的规格是来源材料；与当前明确要求冲突时列出差异，不自动覆盖。

## 五层拆解

1. **体验目标**：谁在什么情境玩，做什么选择，为什么愿意继续。产出简短概念说明。
2. **核心体验流程**：进入、操作、反馈、目标与进度、结束或续玩，以及核心规则和范围。按游戏形态定义一局或一段完整体验。
3. **阶段成果**：每阶段交付什么可体验的版本、验证什么问题、凭什么继续。产出里程碑。
4. **可验收任务**：把当前阶段变成有输入、依赖、输出、边界和验收条件的任务。
5. **实现步骤**：围绕任务选择代码、资源、编辑器配置和验证步骤；技术细节由助手承担。

各层细化到足以支持下一步即可。完整方案应暴露未知，不要求开发前猜完所有细节。

需要写方案、里程碑或任务卡时，读取 [工作模板与拆解方法](references/planning-templates.md)。解释单个概念时无需加载全部模板。

需要定义阶段出口、早期技术验证、范围变更或验收交接时，读取 [交付检查点](references/delivery-checkpoints.md)。

## 决定工作顺序

- 先找出会推翻方向的未知。存在关键未知时，安排回答一个具体问题的小实验，明确成功、失败和后续决定。
- 关键未知较少时，优先拉通一个内容极少但能开始、操作、结束和重来的可玩循环。
- 此后按玩家可感知的增量推进。按玩家动词梳理体验，再补依赖与验收；「一个动词」不天然等于「一个可执行任务」。
- 美术、音频、技术基础也可单独成任务，但要挂到具体阶段成果，并写明接入位置。任务排序结合风险、玩家价值和依赖关系。
- 最小可玩版用于验证循环；达到目标质量的代表性样板用于验证制作方式和成本；之后再扩充内容。小项目按风险合并阶段。
- 原型的质量取决于要验证的问题。视觉辨认类玩法需要有代表性的画面，不能一律将美术留到最后。

## 任务与执行约定

任务卡写清目标、前置条件、要做与不做、交付物、可观察的验收条件、验证方式、集成位置和回退点。一个任务聚焦一个结果，验收可包含多条必要条件。若仍需大范围探索，先拆出有明确问题与时间预算的调查任务；估时标明假设与信心。

每次集成一个可玩增量后，按当前验证授权检查核心循环。区分「构建成功」「功能验证通过」「真机体验通过」，分别报告证据。用户限制验证范围时记录未验证项，保持既有协作边界。

从最小可玩版开始持续集成，在批量扩充内容前验证系统协作；后期再做整体稳定性检查。用需求、阶段或任务、验收证据之间的对应关系检查遗漏与额外工作。

用阶段出口判断能否推进依赖它的后续工作。影响核心循环、技术可行性或既定体验的问题尚未解决时，优先修复、补充验证或缩小范围；未测项目保持未验证状态。

方向、范围和阶段体验需要与用户对齐；已授权范围内的常规实现选择自行处理。用户明确要求逐任务验收时，在相应验收点等待；不默认给每个文件改动新增审批。

用户决定产品目标、范围、优先级和体验是否接受；助手提出方案并处理获准范围内的技术选择和执行。编辑器操作按可用工具与双方约定分配，不默认全部交给用户。

保留可回退版本，记录任务状态和影响后续工作的决定。新想法先记待办，评估对阶段目标、依赖和验证成本的影响，再决定替换当前范围或延后；阻断问题及时处理。

## 按需接入 TapTap

先做可玩循环，再按需求接平台能力、准备发行，最后根据实际反馈迭代。进入平台阶段时读取 [TapTap 路由与来源](references/taptap.md)，并核验当前官方文档及实际工具能力。

H5 是网页运行形态，WebGL 是渲染技术，Cocos 是引擎；技术概念与 TapTap 的产品分类分别确认。CLI、SDK、MCP 或引擎安装不是讨论方法与验证玩法的统一前提。

## 使用边界

这是可复用的方法和可调整的模板，不保存某个游戏的固定场景、参数、本机路径、端口或安装状态。项目决定留在项目方案中。文档参考和技能调用不扩大安装、账号操作、上传、发布或对外沟通的授权。
